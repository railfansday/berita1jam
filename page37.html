Image Playground generates entirely new images, so it’s more what the average person would consider an “AI image.”

Rewiring a running process's output (fd) with gdb

📅 Nov 06, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 6 • Originally published at wada-dev.com

Sometimes you want to re-point a running process's output somewhere else without stopping it. You can do it just by attaching to the process with gdb and calling the close and open system calls directly. Using gdb not as a debugger but as a "tool for rewriting a running process's file descriptors."

There's a long-running process you've left going, and now you wish you'd kept its logs in a file. Or you want to peek at its output from another terminal. Normally you'd restart it with > log.txt appended, but sometimes you don't want to — or can't — stop it.

File descriptors are managed per process, and when you close one, the number gets reused. Using that property, you can close stdout (fd 1) or stderr (fd 2) and reopen a different file, rewiring where the output goes.

First attach to the target process with gdb.

Then just close the fd and reopen it with open. Descriptors are assigned the lowest free number, so if you close 1 and open right away, the return value is 1.

Open a path like "/tmp/app.log" instead of /dev/pts/5 and you switch stdout to a log file mid-run. The second argument to open is the flags; here we pass write-only (O_WRONLY = 1).

When “Working as Designed” Is the Problem

📅 Nov 06, 2026  |  Category: Technology  |  Read Source →

I submitted a security report to Anthropic after Claude Code exposed my .NET User Secrets in its model context. They classified it as “Informative – Working as Designed.”

“Working as designed” is a triage label, not a verdict. But taken at face value, it points to something architectural: security is enforced tool by tool, not around the agent as a whole, and certainly not at the OS-boundary level.

.NET developers commonly use dotnet user-secrets to keep development credentials in their user profile, outside the project tree.

• Other sensitive application configuration

You launch Claude Code in your project directory.

You ask Claude to inspect your application configuration.

And/or read the plaintext secrets.json file.

%APPDATA%\Microsoft\UserSecrets\\secrets.json

Because tool output is returned to Claude, those credentials become part of the conversation context. This is not a vulnerability in .NET. It is a consequence of giving an AI coding agent access to a developer’s local environment.

Anthropic explained to me that Claude Code executes commands with the privileges of the developer’s user account. Their position is that commands such as dotnet user-secrets list require approval in the default permission mode. They also pointed to four security mechanisms:

Fair enough: an agentic tool has to execute commands. Allowlisting dotnet* is on me. But there’s a second problem underneath. secrets.json is unencrypted, so to the agent it’s just another readable file. In any case, their response made me look closely at what those mechanisms actually protect.

{ "permissions": { "deny": ["Bash(dotnet user-secrets list*)"] } }

Now Claude cannot execute the obvious command directly. But what happens if I ask Claude:

“Write a Bash script that inspects my .NET User Secrets configuration and execute it.”

The rule matches the command string, not what the script does. The same applies to Python, PowerShell, compiled executables and any other indirect execution path. PreToolUse hooks can inspect tool calls, but they cannot reliably interpret every script or execution path.

Manual approval doesn’t solve this either. The developer approves running the code, but approval does not limit what the code can reach. Blocking a command is not the same as restricting access to the data that command retrieves.

I then looked at Anthropic’s official sandbox documentation:

https://code.claude.com/docs/en/sandbox-environments

Anthropic offers several sandboxing approaches, and they cover different things. Out of the box, sandboxing is off. You have to enable it first. Once enabled, Bash, PowerShell and Monitor tool commands and their child processes are restricted. Claude’s file tools, MCP servers and hooks run outside it. File tools are gated only by permission rules.

Sandbox-bash is not a comprehensive isolation boundary around Claude Code. Granted, the sandbox runtime srt claude wraps the whole Claude Code process, including file tools, MCP servers and hooks. It is a beta research preview and does not run on native Windows.

On Windows, you need a container or virtual machine to get a sandbox. But here it gets tricky. WSL2 gets dicey fast. By default, WSL2 mounts Windows drives under /mnt, for example:

/mnt/c/Users/yourname/ /mnt/c/Users/yourname/AppData/

Microsoft documents that Linux processes accessing Windows files run with the permissions of the Windows user who launched WSL. On its own, that leaves your Windows profile readable from inside WSL2. Claude will still happily read your secrets, directly or through a tool, and expose them in its context.

Docker is a substantially better option. But the core problem remains the same: a container is only as isolated as its configuration. The difference is that Docker adds a boundary between Claude Code and your Windows host. Unlike WSL2, where your Linux environment can access Windows files through /mnt/c, a properly configured Docker container only sees the files, directories and resources you explicitly expose to it… nah snap… it means that Claude Read still has access to your User Secrets as you need them to launch your app.

Windows has filesystem ACLs, restricted tokens, AppContainer isolation, Job Objects and other process isolation mechanisms. This is not an argument that Windows lacks the necessary security primitives. It is a product limitation: Claude Code’s built-in sandbox does not support native Windows.

So far this has been accidental exposure: Claude runs a command and the credentials land in its context. Now consider deliberate exfiltration.

What happens when an agent has access to both sensitive local data and external tools?

Claude Code supports MCP integrations that can connect the agent to external services and systems. Depending on the integrations configured, these might include:

Now imagine an agent that can read local credentials and also call an MCP server that can send data out. The attack chain is short:

An agent gains access to a local credential or sensitive configuration file.

The credential enters the agent’s context or becomes available to an integration.

The agent invokes an external tool or MCP server.

Sensitive information is transmitted outside the developer’s environment.

A prompt injection could trigger it: malicious instructions in a repository, a compromised dependency, tampered documentation or any other untrusted content the agent reads.

Malicious MCP servers are not far-fetched. A rogue Postmark MCP package has already been found secretly BCC’ing an attacker on outgoing email.1 This is not some exotic theoretical attack; it is a baked-in supply-chain problem.

This is not a claim that every MCP server can access every local file, or that every Claude Code integration automatically permits arbitrary exfiltration. The point is architectural: an agent’s security depends on the combined privileges of all its tools, not just the sandbox around its shell.

The upshot: don’t use User Secrets on a machine where an agent runs. Until agents operate inside a real OS-enforced boundary, stop keeping secrets where an agent can trivially read them.

This is a workaround, not a fix. The real fix is the one I’d still like to see: a consistent, OS-enforced boundary around the whole agent, with native Windows support, shared filesystem policy across all tools, process-tree and MCP isolation, and network egress controls. Until then, don’t leave plaintext secrets lying around next to an agent.

DaVinci Resolve Now Supports Apple’s Brand-New Touchscreen Mac

DaVinci Resolve Now Supports Apple’s Brand-New Touchscreen Mac

Apple’s brand-new MacBook Pro with PROLED XDR display, the first Mac to ever feature a touchscreen, arrives today, and Blackmagic Design’s DaVinci Resolve 21 video editor is ready.

DaVinci Resolve 21.2 introduces many updates, fixes, and improvements, including full compatibility and support for the Apple MacBook Pro with PROLED XDR touchscreen. PetaPixel‘s Jaron Schneider reviewed the new MacBook Pro, awarding it a 10 and, of course, Editor’s Choice.

However, while the big highlight is the touchscreen, it is the fundamentally new Tandem OLED screen technology that truly impresses. Whether users touch it or not, it’s the best display ever in a laptop, absolutely smashing PetaPixel‘s display benchmark tests and delivering truly absurd color performance and consistency.

“This is a remarkable display,” Schneider writes, emphasis his. Between that beautiful display and the MacBook Pro’s class-leading performance in DaVinci Resolve, video editors should be beside themselves, whether they ever use touch inside DaVinci Resolve or not. But now, at least, they can.

The update also adds support for Blackmagic Design Gen 6 LUTs, workflow improvements for audio and multicam clips, support for EXIF data in PNG files, and a bunch of bug fixes. The full list of changes is available on Blackmagic’s support center, and DaVinci Resolve 21.2 is available now as a free update for all Resolve 21 users, including free users and those with the paid Studio version.

The Blackmagic Generation 6 Color Science LUTs and film looks are a notable update. This new color science arrived in September inside Blackmagic RAW 6.0, the company’s professional RAW codec. Your JSON isn't broken — your strings are: escapes, BOMs and the 2^53 lie

📅 Nov 06, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 6 • Originally published at jsonformatter.app

A few weeks ago we published a 30-second audit for spotting JSON tools that leak your payloads. This post is about the other kind of pain: the times JSON "breaks" and it's not the JSON's fault at all — it's the strings, the invisible characters, or a number that silently lied to you.

These are the four failure modes we see most, and what to actually do about them.

JSON strings allow exactly: \" \ \/ \b \f \n \r \t and \uXXXX. That's it.

Test escapes round-trip instead of eyeballing: the JSON escape tool has a minimal mode and an ASCII-safe \uXXXX mode, and the unescape tool validates what comes out instead of silently returning garbage.

A file that looks perfectly fine in your editor but fails with Unexpected token ﻿ is almost always a UTF-8 BOM. The spec (RFC 8259) says producers must not add one — and explicitly lets parsers ignore it. Plenty of parsers don't.

Similarly, content copied from PDFs or Word documents picks up typographic quotes, en-dashes and non-breaking spaces (\u00A0) that are invisible in most editors but structurally fatal. A tree viewer that can display raw escapes makes these obvious in seconds — our JSON viewer does exactly that, and it all runs in your browser.

This is the nastiest one because there's no error.

JavaScript numbers are IEEE-754 doubles, so any integer above 2^53 - 1 (9007199254740991) can't be represented exactly. Parse 9007199254740993 with JSON.parse and you silently get 9007199254740992. No exception. No warning.

The fix is boring but non-negotiable: big IDs travel as strings. If you're auditing an existing integration, paste a real response into a strict validator — ours flags lossy integers before they reach your code.

The most confusing sight in a log: a value that looks like "{\"a\": 1}". That's a JSON document serialized as a string inside another JSON document — logs, webhooks and message queues do this constantly.

Strip one level of escaping, then parse again. For real payloads use something like fromjson in jq running in your browser — no terminal, no uploads, described in our post on client-side jq.

Every tool linked above is 100% client-side: paste your payload, and nothing leaves your browser tab. After the CodeBeautify leak (user-pasted payloads exposed through a public feed), "the tool never sees your data" stopped being a nice-to-have for us — it's the product. The full story is in the leak explained.

Match types, negatives, keyword bids, and impression share – here's what carries over from Google Ads for a paid search team and what doesn't.

In TikTok’s Oct. 30 Q4 product preview, two impression share metrics and a set of ready-to-use keyword packs were given to Search Ads advertisers. I wrote about this preview on Nov. 2. The quick version is that a help page defined those metrics back in September, and the packs are a new addition to the Keyword Suggestion Tool.

The long version is what a paid search manager sees when they open the campaign type for the very first time. A paid search manager has seen match type names, negative keyword lists and the search terms report before as part of Google Ads management. Match type reporting will depend on the campaign objective. Bidding by keyword needs the Traffic objective (along with a Cost Cap bid).

In each of these areas, for that manager, it becomes an issue of whether they can continue using some old habits they’ve developed, or if they need to change how they’re setting up their account and creating their reports. Each of these areas is addressed in TikTok’s help center.

Search advertising on TikTok has evolved sequentially during a four year period with the help center separating each addition. Brooke Osmundson reported that TikTok ran a search ads beta with select partner accounts in March 2022. The Search Ads Toggle was then made available to users in 2023. This is currently referred to as Automatic Search Placement, which extends in-feed ads into search result pages. All new campaigns will automatically be enabled with Automatic Search Placement. As noted by the help center at TikTok, Automatic Search Placement is considered “not a traditional keyword-based search ads offering.”

The keyword product Search Ads Campaign went live in the U.S. on Sept. 24, 2024. The two supported objectives were Traffic and Web Conversion. Also included with this launch were the keyword suggestion tool and negative keywords. At TikTok World in June 2025, TikTok stated “Billions of searches are happening on TikTok every day,” “up more than 40% from last year,” according to internal global data provided by the company, and did not provide an exact number.

On May 13, 2026, TikTok announced Search Hubs. This is a brand-owned page displayed above the search results for an approved list of keywords. TopSearch, which has a help center page dated October 2026, is a top-of-the-page auction for the first sponsored position and is billed per thousand impressions when using the Reach objective. When an advertiser loses in the auction, their ad “does not move into a lower search ad placement.” On Oct. 5, 2026, TikTok announced “Search Ads Campaign, powered by Smart+,” however there was no information regarding rollout dates in the post.

Automatic Search Placement, Search Ads Campaign, the Automated Keywords setting within Search Ads Campaign, Search Hubs and TopSearch are separate products and options; however the focus of this comparison is the Search Ads Campaign. The campaign page lists Traffic, Sales, Lead Generation and App Promotion as objectives. Additionally, the bottom of the campaign page states “available in the US and testing in other markets,” while TikTok’s availability page, dated April 2026, lists 11 countries for Traffic.

Keyword matching types on TikTok are called by the same name and have the same format as with Google Ads. On TikTok’s match type page it is explained that there are broad, phrase and exact. Phrase and exact are defined on the meaning of the search rather than its word order, so a phrase match for “Luxury fragrance” will also match a search for a specific perfume name. TikTok’s keywords page states you can have up to 1,000 keywords per ad group, but recommends you have at least 20.

Negative Keywords in both platforms have the same three match options, and TikTok allows a maximum of ten thousand negative keywords per ad group. As for plurals and synonyms, both platforms require the advertisers to include these variations. The platforms differ on misspellings. Google’s negative keywords automatically account for them. However, according to its documentation, TikTok’s negative keywords “don’t block singular or plural forms, misspellings, and synonyms” and “You must add each variation separately.”

TikTok’s search terms report is located where an individual managing a Google Ads campaign would look for it. In addition, TikTok’s reporting guide, dated April 2026, lists performance reporting at the search term, keyword and ad group levels. Traffic campaigns support keyword-level bids under Cost Cap. According to TikTok’s optimization guide, if a keyword has no assigned bid, the bid for that keyword will inherit the bid from its parent ad group.

TikTok’s Keyword Suggestion Tool generates “monthly impression predictions” it says “are based on historical data and are for reference only.” TikTok’s Keyword Planner provides “search volume, competition, and scale and performance prediction.”

The Oct. 30 preview of Keyword Packs includes pre-crafted lists of brand and category keywords. These lists generate “daily-refreshed recommendations” which include “key signals like search volume, CPC, and competition.”

The Impression Share help page, dated September 2026, has definitions for Impression Share as “The percentage of eligible search results impressions your ads captured” and Top 1 Impression Share as the same share of first-position impressions. The preview states Impression Share and Top 1 Impression Share are available at the campaign, advertiser and keyword levels. A health module in an ad group at the time of creation identifies thin keyword lists, low bids and a daily budget less than five times the bid.

Keyword-level bidding is documented for Traffic campaigns using Cost Cap, and the optimization guide says it “is based on the cost cap bidding, so it shows only when there is a valid bid.” The guide covers Web Conversion only through Target CPA but does not include keyword bidding. There is also an additional reporting restriction on match type keyword reporting, this one is Traffic only, and nothing on the pages reviewed as of Nov. 4 covers either control for Catalog or App Promotion campaigns. TikTok’s Automated Keywords feature, per a help page dated March 2026, is enabled by default for SMB accounts which “have to opt out or turn the toggle off,” while Key Accounts have the setting switched off by default.

TikTok’s page says “You aren’t notified when new automated keywords are added to a campaign.” Automated Keywords may be controlled with the toggle switch, by pausing an individual keyword, or through the use of negative keywords, and TikTok says its own internal testing showed the feature “can drive 10% incremental conversions while meeting CPA targets.”

All ads are either videos, carousels or, for Sales/Travel & Entertainment advertisers, a Search Catalog format. TikTok’s optimization guide says relevance is scored for each keyword and creative pair. Google measures ad quality as well; therefore, it is not the creative that differs between platforms. The production does differ because a campaign needs creative that fits each keyword theme.

Where the campaign type is sold varies based upon the objective of the campaign. TikTok’s availability page has two different country lists for Traffic. The first list includes Brazil, Australia, and all other countries’ advertisers who are trying to reach users in the U.S., and the second list includes Japan but not Brazil, Australia or the rest-of-world provision. Lead Generation campaigns are listed as available in the U.S. only. TopSearch campaigns are available to “Select accounts in supported markets,” and there are 20 countries listed for TopSearch.

Top 1 Impression Share is a related measure to Google’s Search absolute top impression share. The latter counts the number of impressions from “the very first ad among top ads” against the estimated number of impressions the advertiser would have been eligible for out of all the top ads. While both TikTok pages define the base of their metrics differently, “eligible search results impressions” according to the help page and “eligible search auctions” according to the preview, there are no publicly available resources showing the two platforms count the same way.

TikTok’s reporting guide says that keywords and search terms with low conversions “cannot be disclosed individually,” which “may cause a discrepancy in total conversions.” Keyword reporting is described as “a landscape report to provide insights on top-performing keywords” and full analysis, it says, should be done at the ad group and campaign levels, and not at the keyword level.

The keyword report provides you with the best-performing keywords, but may not reflect your campaigns’ total conversion numbers.

On the same reporting guide page it states that advertisers are unable to report on search terms or keywords broken out by creative (because of privacy). Data for iOS14 SKAN (Apple’s SKAdNetwork) for conversion, CPA, and conversion rate for Search Ads “are not currently available for the search ads campaign.” Brand safety and viewability measurement from third-party sources on the results page “may be subject to limitations.”

In addition, search campaign metrics lag behind by about eight hours. The guide says “Partial conversions will be available to advertisers after two days” and “Most conversions will display after three days.”

The automated terms report displays all automated terms as a single line item, with a drop-down menu showing the ten highest spending terms, the Automated Keywords page states. In addition, a search term that matches without an explicit keyword can display as “unknown.”

Neither the Impression Share help page nor the reporting guide indicates how to separate lost impression share by budget and by rank. On their help page, they list budget, bidding, keyword coverage, creative relevance, competition and changes in search demand as possible things to look at when assessing lost impression share; and sort the first two (budget and bidding) by if you spent your entire budget. Google’s page, by contrast, splits lost share into separate budget and rank metrics.

Reddit announced a test of ads in its search pages on Nov. 3 with a select group of eligible advertisers. The announcement says ads “may appear based on a range of factors, including contextual relevance to a user’s search query,” using Reddit’s existing targeting. It does not describe keyword controls.

In March 2023, Instagram announced ads in search results, showing “in the feed that people can scroll when they tap into a post from search results.” Both platforms announced a placement, while TikTok documented its keyword tools, a distinction for search teams to work with.

When you initially open the TikTok account, one of the first things you’ll recognize will be the search terms report. A manager who runs weekly Google search term reviews already has the expertise for that review, the negative keywords, and the ‘unknown’ rows.

The second item to verify when opening the TikTok account is whether the Automated Keywords toggle is turned on. The feature is enabled by default for SMB accounts, and additions arrive without notice.

Your campaign objective follows your business goal. According to TikTok’s optimization guide, if you run a Web Conversion campaign that cannot build volume, you can “temporarily switch to the Traffic objective to build volume,” and return to Web Conversion once the campaign is stable. During the Traffic phase, you can view match-type reporting and use keyword-level bids under a Cost Cap bid. Both of these disappear when you return to Web Conversion. However, keyword targeting (and its corresponding negatives), along with the search terms review, remain throughout.

Producing assets that match the keyword themes means working with whoever makes the company’s TikTok creative. Keyword totals show the top performers, TikTok points overall analysis to the ad group and campaign, and iOS14 SKAN conversion data is missing, so a cross-platform report needs a TikTok search row that says what it can and cannot show.

eMarketer’s U.S. search ad revenue forecast “excludes display-oriented formats on social networks, even if triggered by search queries,” and its social network ad spending forecast “includes all the various formats of advertising on those platforms.” That is how eMarketer draws its lines. This is useful context for anyone comparing TikTok search spend with its reported figures, though it doesn’t clarify where a company records the expense.

TikTok describes TopSearch as a visibility product. Its help center lists “brand, category, competitor, seasonal, or tentpole queries.”

As such, competitor queries listed as part of TikTok’s own lists constitute a brand-defense use case to assess, not a budget line to assume.

Paid search skills apply directly to TikTok’s keyword campaigns. The objective, automation defaults, creative requirements and reporting limits determine how far they carry. Budget ownership is still a company decision.

The campaigns for holiday promotions currently being run will be the ones described through the Impression Share columns in Ads Manager, on accounts where it shows them.

In addition, this quarter there will be a keyword-level read of spend on accounts that have the metrics. All accounts that have Automated Keywords enabled will see how those terms performed in campaign reporting and in the search terms report.

Reddit’s test is one to watch for anything more on search-specific keyword controls.
