Why an Agent Hardcodes Environment Config in Source

📅 Nov 07, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 7 • Originally published at powerduck.com

Quick answer: Environment config belongs outside the source because it changes between development, staging, and production while the code stays the same. When an agent writes a URL, bucket name, or connection string as a literal to make the current run pass, it bakes one environment's values into every deploy. Read environment-specific values from a single config layer, validate them at startup, and keep secrets out of the repository.

A literal is the shortest path to a green run. The agent needs a value to proceed, the environment is not defined, and typing it inline removes the friction immediately. Training data is full of examples with hardcoded endpoints, and unless the task explicitly asks for externalized config, the agent optimizes for working code on this machine rather than portable code on the next.

The failure is silent at first. It works on the agent's machine because that literal happens to match the local environment. It breaks when the same code points at a development database from production, when a host name changes and requires a full rebuild, or when a committed credential has to be rotated by editing source.

Not every literal is a problem. Values that never change between environments, like a fixed page size or a well-known constant, can stay in code. The dividing line is whether the value differs by environment or deployment. For how this fits the broader work of running coding agents well, see the AI coding agent guide.

Use one loading point. Read the environment once, in a single module, and expose typed values to the rest of the app instead of reading process variables ad hoc across the codebase. That gives you one place to audit and one place to fail.

Provide safe defaults for non-sensitive values and let the environment override them, but never guess a missing required value. Validate that every required variable is present and well formed at startup, and fail fast with a clear message before the app handles traffic. Keep secrets in a secret manager rather than a committed .env file; a local .env, listed in .gitignore, works for development as long as the required variables are documented.

Centralizing reads also makes the configuration discoverable. When every variable enters through one module, you can list the full set of environment dependencies in a single place and confirm nothing reads a variable the startup check does not know about. Scattered reads hide unused and missing variables, and they make a secret harder to locate because it could be referenced anywhere in the codebase.

Keep defaults honest. A default works for a non-critical value with a safe fallback, but it should never point at a real resource. If a missing production variable silently falls back to a development endpoint, the problem stays hidden until the wrong data is written. Required values should raise an error rather than inherit a convenient default.

For the boundary with a related failure, committing a machine-specific absolute path is a separate portability problem; here the issue is values that legitimately change between environments. Powerduck keeps environment-specific values in scoped variables rather than literals, with globals, collection, environment, and local scopes, and when no base URL is available it asks for one instead of guessing, which is the same fail-fast rule applied to request configuration.

Is a .env file enough? For local development, yes, as long as it is not committed and secrets are excluded. In production, prefer a managed secret store and inject values through the platform.

Should I externalize every constant? No. Move only values that change across environments or deployments. Externalizing stable constants adds indirection with no benefit.

What if the agent keeps hardcoding values? Make externalization part of the task and the review. Require the config layer up front and reject any diff that introduces an environment-specific literal.

Code is built once and deployed many times; environment config is the part that changes between those deployments. Keep the two separate, load config through one validated entry point, fail loudly when a required value is missing, and never commit a secret. A run that passes on a hardcoded value is only passing for one environment.

A filterable table that still works with JavaScript off

📅 Nov 07, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 7 • Edited on Nov 7 • AI-assisted

I made a small page for health.dailyappslab.com that filters 259 US fast-food menu items by protein and calories. The filtering is the easy part. What I cared about was that the page still shows everything when the script doesn't run.

The data is one TypeScript file. Each item has a chain, a name, calories, protein and a few optional fields like sodium. Each chain entry also stores the nutrition page the numbers came from and the date I read it, so the source sits next to the data instead of in my memory.

Astro renders every item as a table row at build time. Each row carries its values as data attributes:

"Protein per 100 calories" is computed once in the data file, not in the browser:

With JavaScript off, you get the full table, already sorted by that number. Crawlers that don't run scripts see the same page.

The script only hides and reorders rows. It reads the form, filters the rows by their data attributes, sorts what's left, and sets hidden on the rest:

There is no framework on the page and no fetch call. The table is already in the DOM, so the script only moves rows around.

The filters also live in the URL. After each change the script writes them with history.replaceState and URLSearchParams, and on load it reads them back, so a filtered list can be shared as a link. The form is a plain GET form to the same path, which makes it behave sensibly as markup. Since the site is static, though, the server ignores the query string and only the script acts on it.

Two limits. The numbers are a snapshot: I copied them from each chain's own US nutrition page on the dates shown in the page, so they will drift when menus change. And they are US menus only. All 259 rows were checked against the article tables they came from before the page went live. If the data grows, a script that runs that comparison on every build is what I'd add first.

If you want to see it run, the page is here: https://health.dailyappslab.com/macroscout/protein-finder/. It's free and needs no signup.

Magnus Ditlev Sets New Iron-Distance World Best With 7:19:17 at Ironman Florida

📅 Nov 07, 2026  |  Category: World  |  Read Source →

Magnus Ditlev set the fastest-ever Iron-distance time at the 2026 Ironman Florida (Photo by Sean M. Haffey/Getty Images for IRONMAN) (Photo: Getty Images for IRONMAN)

One month after a heartbreaking DNF in Kona, Magnus Ditlev (DEN) rode away from the field at Ironman Florida and never looked back. His 7:19:17 took 1:47 off the previous men’s iron-distance world best that Sam Laidlow (FRA) set at Challenge Roth earlier this year.

Florida was a chance at redemption for Ditlev, who had come agonizingly close to winning the Ironman World Championship in Kona. He’d taken the lead late on the bike and looked on course for the win until he abruptly came to a stop on the run with roughly 30 minutes of racing left.

However, ahead of Kona, Ditlev said he was putting up career-best numbers across the swim, bike, and run at his training camp in Colorado. In Florida, he finally got to reap the rewards of what fitness could produce all the way to the finish line.

Ditlev came out of the water in fifth, right on the heels of Ben Kanute (USA) and Rudy von Berg (USA). He took his time in T1 and started the bike nearly a minute down, but it didn’t take him long to ride back to the front. And then, just past mile 10, he made his move. No one could go with him, and they wouldn’t be able to stay remotely close to him either.

By the time Ditlev came off the bike, he was 11 minutes clear of a chase group that included Sam Long (USA), von Berg, and Kanute. His 3:51:16 was the fastest bike split ever recorded at an Ironman, nearly two minutes quicker than the 3:53:12 Robert Kallin (SWE) rode at Ironman Kalmar in August.

Off the bike, he once again took his time in transition. But transitions were the only slow part of Ditlev’s day. Once through T2, he picked up another minute on the chasers over the opening 10 miles. He hit halfway in 1:15, on pace for a 2:30 marathon and well within reach of Laidlow’s 7:21:04. With such an unassailable lead, one can assume he must’ve known the record was within reach to keep such an aggressive pace.

Ditlev eventually closed with a 2:33:31 marathon, crossing the line in 7:19:17. Von Berg took second, 14 minutes back, securing the early Kona slot and podium he’d come for. Matt Hanson (USA), meanwhile, ran a remarkable 2:28:07 to beat Long to the final podium spot, but still finished 16 minutes behind Ditlev.

"This trailer is my way of saying goodbye": Have a listen to the Mass Effect 5 score that could have been, courtesy of one of the original games' composers

📅 Nov 07, 2026  |  Category: Technology  |  Read Source →

By this point I'm probably safe in assuming that you all know EA are shutting down BioWare, and that Mass Effect 5 has been cancelled in turn. You may have also seen that an internal trailer for Mass Effect 5, or Universe as it was seemingly going to be called, was leaked not long after the news broke, and that Sam Hulick, one of the composers on the original trilogy of games, shared he was going to offer up his re-scored version of the trailer. Well, it's N7 Day, as rough as that will be for many of the developers on the game, but Hulick has stood by his word, and shared an oral glimpse at what the world of Mass Effect Universe could have sounded like.

You can check out this new version of the trailer below, perhaps pop it on while you have a read of the rest of this post, as Hulick did also write in a Patreon blog about his experience with the series. "As part of my own closure, and as a love letter to the fans, I really wanted to re-score the leaked Mass Effect Universe trailer in time for N7 Day this year," he wrote. "BioWare edited a killer track called “Quartz” by French 79 to fit their trailer, which I think hinted at a slight directional shift in the score. Using that as inspiration, along with the musical tone from my work on the first three Mass Effect games, I hit the studio and got to work."

As it turns out, BioWare had actually reached out to Hulick asking him to potentially do some work for the project. "This year, BioWare emailed me asking if I was interested in working with them on an internal demo, and they said they were 'hoping to get some music written that would feel like Mass [Effect], supporting our new direction.' Of course, I said yes!" This doesn't mean he wouldn't have composed the actual game, as a composer hadn't been officially selected, but Hulick said he was "more than happy to collaborate on the new game’s musical direction and help make their internal demo sound as good as it could."

Hulick also spoke of some of the ideas he had for the direction Mass Effect Universe's soundtrack could take, noting how he "thought it would’ve been incredible to bring more songs with lyrics into the game," considering how many people loved the first game's end-credits song. "This would’ve been a great way to highlight more emotional moments in the narrative. Artists at the top of my collaboration list included Gunship, NINA, and The Midnight, all of whom have a moody, cinematic synthwave vibe that would’ve meshed well with the score in my head. And I’m pretty sure the Gunship guys are gamers, and if they’re Mass Effect fans, that would’ve been the icing on the cake!"

Of course, with the studio now closing, this never got to go very far, the news hitting Hulick "particularly hard, as the Mass Effect trilogy is a core part of my origin story as a composer." For the composer, ultimately "this trailer is my way of saying goodbye… at least for now." This continues to be a horrendously sad moment in the industry! As always, solidarity with the team at BioWare.

Reba McEntire Reveals Dolly Parton’s Touching On-Set Gesture: ‘She Didn’t Have To Do That’

📅 Nov 07, 2026  |  Category: Sports  |  Read Source →

Reba McEntire was determined to make Dolly Parton feel welcome when the country legend joined her sitcom for a guest appearance—but it was Parton who ended up making everyone on-set feel special.

While speaking at NAR NXT in New Orleans alongside her manager and former real estate agent, Justin McIntosh, McEntire recalled the thoughtful gesture Parton made for every crew member behind the scenes of her hit sitcom “Reba”—a small act of kindness that left a lasting impression.

Instead of simply showing up and delivering her lines, Parton made a point of personally greeting the people working behind the scenes, bringing along Valentine’s Day candy and a message for every crew member.

For McEntire, the gesture remains a vivid example of the warmth that made her fellow singer so beloved.

“I was so nervous with Dolly being on the set. I wanted everyone to be nice. What I didn’t expect was how nice she was going to be on the set," she said.

McEntire recalled that Parton took the time to make each person feel appreciated, turning a guest appearance into a chance to connect with the crew.

“She had Valentine’s Day candies, and she went to every crew member individually and said how happy she was to be there,” she said. “She didn’t have to do that.”

The memory has stayed with McEntire, along with a conversation the two shared while sitting together on the iconic show's couch.

“I asked her if she would ever retire,” McEntire recalled. “And she said, ‘What would I do that I could have so much fun doing?’”

It was a simple answer, but one that reflected the enthusiasm McEntire remembers so fondly.

“I’ve never met a person or known a person that’s so universally loved like Dolly Parton,” she said. “I’ve never heard anything bad about her. She was that special of a person.”

That sense of gratitude for a career filled with opportunities to connect with people is something McEntire shares.

“I’m just really grateful and thankful for doing what I do at the level I do,” she said.

For McEntire, keeping her work exciting means giving herself room to try new things—and inviting her audience along for the experience.

“When I change things up, my fans stay interested with me,” she explained. “If it looks like I’m having fun, then they’re having fun.”

The actress revealed that being able to enjoy her work is a gift.

“If you are doing what you love, then that’s how blessed you are,” she said. “That’s one of the greatest gifts God can give, to give you a job you love. I’m very grateful for my job.”

The connection she has built with her audience also rests on the principle that people can recognize sincerity principle—something she believes applies well beyond entertainment.

“I try to sing the songs from my heart so when you listen to it, it touches your heart,” she said.

That emphasis on warmth and connection carries into the way McEntire searches for a home, too.

Long before her career brought her to stages and television sets, she grew up on an 8,000-acre ranch in Oklahoma.

Despite the expanse of land outside, her family of six shared a small house with three bedrooms and one bathroom.

Asked what she first thinks of when she remembers the ranch, McEntire named the people and feelings that filled it.

“Love, family, unity, closeness,” she said. “One itty-bitty bathroom, three bedrooms. We were a close family.”

Gathering around the dinner table was part of life, and the atmosphere of the house remains easy for her to recall.

“We all sat at the dinner table together,” she said. “It was earthy. I can still smell how the house smelled and the energy.”

The land remains a family home. McEntire says it stayed in the family after her parents died, and her sister and her sister’s family now live on the property.

Those early memories offer a glimpse of what McEntire still values when she walks into a house: a feeling of comfort and a connection that goes beyond its appearance.

“A house has energy, and when you come in and when you bond with that energy, it makes it a home,” she said. “So I always look for good, positive energy when I come in.”

The country icon reflected on the moment she experienced that pull while looking for property in Tennessee.

A friend who was vacationing in Florida with a real estate agent spotted a listing the agent was viewing and urged that it be shown to McEntire.

“My friend said, ‘You gotta show Reba that place,’” she recalled.

The approach to the property and a creek at the back helped capture her attention. Soon, she was returning for visits and spending time with the owners.

“The love I had for that house, it took my breath away,” she said. “I went a couple times, and I watched football games with the owners.”

When it comes to her priorities in a home, being comfortable and enjoying the surroundings rank high.

“I love a home with a view,” she said. “When I lived in Oklahoma, you could see sunrise and sunset. That’s important to me.”

McEntire said that focus on people and their needs also helped draw her to her partnership with Realtor.com®.

“What y'all do is very important, you care so much, that's why I like Realtor.com. I love your organization because you have heart...You really do dive into the family and what their needs are. You love people and you care about people, that's why I wanted to be with you guys," she said.

Whether she is discussing finding a home or maintaining the trust of an audience, McEntire returns to the importance of treating people well—and continuing to do so over time.

“You have to stay consistently honest, because when you look someone in the eye, they know how you treated them last time,” she said. “You have to stay consistent with it.”
