Skooner turns a Kubernetes service-account token into a dashboard session

📅 Nov 11, 2026  |  Category: Technology  |  Read Source →

Skooner is a Kubernetes dashboard that can read and change cluster resources. Its install guide supports service-account tokens, OIDC, and a NodePort access path. The token that a user enters can inherit substantial cluster authority. A ZoomEye title count is useful for finding possible dashboards, but the token's role bindings and lifetime are the security decision.

On 2026-11-11 at 19:48 UTC, title="Skooner" returned 1,571 ZoomEye matches with sub_type=all, page 1, and page size 1. The application field returned zero, the body field returned 1,574, and the legacy title="k8dash" candidate returned 64. The product's former name is a reminder that inventory queries need a rename check.

The search is available at ZoomEye. A title match does not prove that a cluster is reachable or that the token exposed on the login screen has cluster-admin rights.

The installation instructions describe a service account and a token secret. A user copies that token into the dashboard login. The dashboard server proxies requests to the Kubernetes API. If the service account is bound to a broad role, every session using the token inherits that authority.

Create a dedicated service account for the dashboard and bind only the roles the operators need. Prefer OIDC and short-lived credentials when the cluster supports them. Do not reuse the cluster-admin token from a bootstrap process as the daily dashboard login. Test read, list, create, and delete operations separately for each role.

The install guide offers a NodePort option for quick access. A NodePort is a network exposure decision, not just a service configuration. Restrict it with network policy, a firewall, or an authenticated proxy. If the dashboard is only for a few administrators, a private address or port-forward is safer than publishing the NodePort.

Test from an untrusted network and confirm that the login page and any API routes are not reachable. Then test from the approved administrative network. Record the ingress path, TLS termination, and authentication method so that a later service change does not silently remove them.

The dashboard can update YAML, scale workloads, and manage resources. Enable Kubernetes audit logging and review the service account and user identities that appear in the logs. Alert on token creation, role-binding changes, secret reads, and resource changes made through the dashboard namespace.

The 1,571 title matches are not a count of vulnerable clusters. They are a seed for checking token scope and network placement. Skooner is useful when its login token is a narrow, expiring identity and the dashboard is kept on an administrative path.

Google introduces Gemini Decisions API that scores 1,000 closed-set choices in a single pass

📅 Nov 11, 2026  |  Category: Technology  |  Read Source →

📅 November 11, 2026 • Google blog — Google introduced the Gemini Decisions API, a new endpoint for fast closed-set decisions, powered by a new model, Gemini Decision 1 (gemini-decision-1), via the Gemini API in Google AI Studio. Instead of generating answer text token by token, Gemini Decision 1 scores candidate options in a single forward pass and returns probabilities plus confidence scores. One request carries a shared multimodal input across text, images, audio, video and PDFs of up to 256K tokens, with up to 1,000 independent questions evaluated against it.

Three question types, one confidence score Questions come in three types: a yes/no probability called noul, multiple choice with 2 to 255 options returning normalized probabilities for every candidate, and ordered rubric scoring returning a continuous weighted score with per-level probabilities. Every answer includes a confidence score from 0 to 1, so code can route ambiguous cases to a fallback or a human reviewer. Purpose-built use cases named by Google are tool selection, policy checks, model routing and context grading. The confidence score lets code gate on certainty.

Latency and pricing Google reports end-to-end latency of 150–250 ms, median model compute of 50–100 ms contexts up to 16K tokens, with latency nearly flat from 1 to 100 questions per request. Pricing: USD 0.10 per 1M input tokens with zero output tokens billed. Per Google, this makes it nearly 5x cheaper across a shared benchmark suite than Gemini 3.5 Flash-Lite with the Interactions API. A no-cost tier exists in Google AI Studio. Per Google, it leads benchmarks in routing, reasoning, ranking and multimodal understanding with the lowest calibration error.

Where Google runs it and what changes Per Google, internal uses include dynamic model routing in Gemini Notebook with up to 40 percent lower latency for daily queries, wireframing in Stitch, emoji selection in CC from more than 200 options, and a safety layer for MCP tools in Google Search. Integrations are rolling out with OpenRouter, LangChain, Vercel AI SDK, LiteLLM, Pydantic AI, Pipecat, LiveKit and OpenCode alongside the google-genai SDKs.

IMPACT — for agent builders: one-pass scoring changes the cost of routing, ranking and policy checks inside agent stacks.

Stripe approved the payment. That's not the question a license-key store needs answered.

📅 Nov 11, 2026  |  Category: Technology  |  Read Source →

Here's a fraud scenario physical ecommerce rarely has to think about.

Someone buys a game key with a stolen card. The key is revealed instantly. Within minutes it's redeemed, or resold on a grey-market site.

Weeks later the chargeback arrives. You refund the money. You don't get the key back. No package to intercept, no return to process, no address to flag. The product left the moment the page loaded.

That's daily life for Increddy, a license-key storefront, and it's why "Stripe handles fraud" wasn't enough.

Payment processors rank digital goods among the highest-risk categories, and the reasons stack up:

Every risk decision that matters has to happen before checkout completes. Afterwards, you're just counting losses.

To be clear: Stripe's fraud tooling is good, and it stays in Increddy's stack. It scores the payment (card, device, transaction pattern) against signals from across Stripe's network.

It doesn't answer "is this payment risky **given that the product is an instantly resellable key we can never claw back?"

Those are different questions, and a key store needs both answered.

The design choice that matters isn't any single fraud rule. It's where the risk check sits.

A check that runs after Stripe approves is only reacting to a decision that's already been made. So Increddy's risk scoring is a first-class Medusa module inside the checkout flow with the authority to block checkout completion on its own, whatever Stripe returned.

It gets a vote before the order exists, not a note attached to a transaction that already happened.

You might have noticed there's no list of signals or thresholds in this post. That's deliberate.

It's the same reason banks don't publish their fraud rules: a risk system works partly because the people it targets can't read the rulebook. The architecture is worth sharing. The heuristics aren't, because publishing them would make them worse at their job.

Treat fraud risk as a property of the product category, not only the payment. If what you sell is valuable the instant it's delivered and impossible to take back, give your own risk logic a real seat at checkout, with real veto power.

I Deployed My First Django App on Shared Hosting and Broke It 7 Times. Here's What Fixed It.

📅 Nov 11, 2026  |  Category: Technology  |  Read Source →

description: The real, unfiltered story of getting Django live on cPanel/DirectAdmin-style hosting, with the exact mistakes and fixes. tags: django, python, webdev, beginners cover_image: The "It Works on My Machine" Lie My Django app ran perfectly on localhost:8000. Beautiful pages. Zero errors. I felt like a genius. Then I uploaded it to a real server. 500 Internal Server Error. No message. No hint. Just a white page staring at me like it knew what I'd done. If you've ever lived this moment, this post is for you. Here are the 7 ways I broke my deployment, in order, so you can skip straight to the fix. Break #1: Debug Mode Was Hiding the Truth On my laptop, DEBUG = True showed me friendly error pages. In production, DEBUG = False showed me nothing. The fix: Check your server's error log first, before touching any code. The answer is almost always sitting there in plain text.

DEBUG = False ALLOWED_HOSTS = ["yourdomain.com", "www.yourdomain.com"] 💡 Forgetting ALLOWED_HOSTS is the #1 reason a fresh deploy fails. Break #2: My Static Files Vanished The site loaded, but with no CSS. It looked like a 1998 homepage. Django doesn't serve static files in production the way runserver does. You have to collect them: STATIC_URL = "/static/" STATIC_ROOT = BASE_DIR / "staticfiles" python manage.py collectstatic Then point your web server at that folder. Suddenly, colors. 🎨 Break #3: Wrong Python Version My laptop ran Python 3.12. The server defaulted to 3.8. Cue a dozen cryptic syntax errors. The fix: Create the app with the right Python version in your host's "Setup Python App" panel, and always pin your versions: pip freeze > requirements.txt Break #4: Secrets in the Code (Please Don't Do This) I almost pushed my SECRET_KEY to GitHub. Almost. import os SECRET_KEY = os.environ.get("DJANGO_SECRET_KEY") Move secrets into environment variables. Your future self will thank you. So will your bank account if you ever add payment keys. Break #5: The Database That Wasn't There SQLite worked locally. On the server, I hit migration errors and file permission problems. Two lessons: Run python manage.py migrate on the server, not just locally. For anything serious, switch to MySQL or PostgreSQL and keep credentials in environment variables. Break #6: The Passenger/WSGI Confusion Shared hosts don't run runserver. They need a WSGI entry point that tells the server where your app lives. If your app won't start, check that your startup file points to the right module: from myproject.wsgi import application One typo in the project name = instant 500. Ask me how I know. Break #7: I Never Restarted the App I fixed the bug. Refreshed. Same error. I fixed it again. Same error. For an hour. The app was still running the old code. Every time you change something on the server, restart the application. It's a button. It's always been a button. My Deployment Checklist (Steal This) [ ] DEBUG = False [ ] ALLOWED_HOSTS set correctly [ ] Secrets in environment variables [ ] collectstatic run [ ] Correct Python version selected [ ] requirements.txt installed on the server [ ] Migrations applied [ ] App restarted [ ] Error logs checked first when something breaks The Real Lesson Deployment isn't a separate skill from coding. It's the moment your code meets reality. Every error I hit taught me something about how the web actually works: what a server does, where files live, why configuration matters. Breaking things 7 times made me a better developer than 7 tutorials did. So if your first deploy is on fire right now, good. You're learning.

Your Turn 👇 What's the worst deployment bug you've ever hit? Drop it in the comments. I'll bet someone has a story that tops "I forgot to restart the app." And if this saved you an hour of panic, a ❤️ helps other beginners find it.

PlayStation Plus is undergoing several major changes in November, from the announcement of the closure of its PC cloud streaming app to the addition and removal of several high-profile games. Indeed, it is a very busy month for the platform, and one that users should approach with equal levels of excitement and trepidation. This is especially true of November 17, a day that will prove to be both a huge win for many PlayStation Plus users and a frustrating experience for many others.

Alongside the aforementioned closing of a major PS Plus feature, November will mark the departure of some of its very best games, all of which are leaving for one specific reason. However, November 17 will also see a huge wealth of titles be added to the service, many of which have never been on PS Plus before, and several of which are fairly recent releases. For most PlayStation Plus fans, this will all feel rather familiar, but it is still worth paying attention to, especially for those who love Rockstar's games.

Of course, the big additions include Death Stranding 2: On the Beach and Atomfall, two exceptional titles that offer vastly unique experiences. Frankly, the whole selection of new PlayStation Plus titles shares that in common, the vast breadth of genres on offer proving to be a huge boon to the service. If you have PlayStation Plus Premium, then the addition of these two lesser-known cult classic titles is also a huge win, especially Soul Reaver 2, which is an underrated PlayStation 2 game.

Dragon Ball Officially Introduces The One Cosmic-Level Threat Even Goku And Vegeta Can’t Beat

📅 Nov 11, 2026  |  Category: Sports  |  Read Source →

Goku, Vegeta, and many of their strongest allies have taken on many powerful foes capable of destroying entire planets, but Dragon Ball Super: Beerus has successfully helped make a cosmic-level threat more intimidating than ever. New scenes and drastic edits have helped make Dragon Ball's newest anime a big improvement over its original release, but certain clever changes are heightening the source material in ways that are making the series more than a simple remaster. Especially with how The God of Destruction is now being portrayed.

Dragon Ball's creator, Akira Toriyama, consistently loved to inject comedy and light-hearted adventures into his work, and it was blatantly apparent in Dragon Ball Daima. Most of Dragon Ball Super's filler material included that sort of content that has been heavily redacted from the newest anime series that aims to condense the first 41 episodes of Dragon Ball Super into 19. While the revised series isn't completely void of comedic scenes, its dedication to making Beerus more frightening has been a success.

While many of Toei's questionable decisions held Dragon Ball Super's original anime back from reaching the heights it eventually achieved, Dragon Ball Super: Beerus has drastically improved the source material's most controversial moments. Goku's first battle with The God of Destruction on King Kai's planet is the clearest example of improvement. Episode #5 of the latest anime helped establish that Beerus is far more than a tough enemy who could destroy Earth; he's a threat to the fabric holding Goku’s reality together.

In Dragon Ball Super: Beerus episode #5, The God of Destruction finally gets his wish of fighting a Super Saiyan God. Goku takes some time to get used to his new divine power boost, but it doesn't take long for the two fighters to start taking each other more seriously, especially when their battle reaches Earth's upper atmosphere. It was there that Goku's ability to protect his home world was tested, and it's when the best look at Beerus's potential is realized.

With Dragon Ball being one of the most beloved anime worldwide, it's disappointing that Toei continues to make the same mistakes that hold it back.

During the Battle of Gods film and original Dragon Ball Super anime, Beerus pushes Goku's limits by sending a flurry of small, shiny purple energy balls towards Earth. Since each attack was capable of destroying the planet, it was up to Goku to stop every single one. However, episode #5 of Dragon Ball Super: Beerus makes visual changes to the energy balls that make them look far more menacing than a typical Dragon Ball energy attack.

The Dragon Ball Super: Broly movie introduced the concept that when powerful enough energies clash, the fabric of reality can buckle. This was visually represented with a strange, colorful effect filled with inverted mixes of purple, green, and blue that completely took Gogeta by surprise during his fight against Super Saiyan Broly. Now, a similar effect has been added to Beerus's energy balls, making them seem a lot scarier than their previous representations.

As Beerus kicked around one of the orbs like a soccer ball, each time he tapped it, the reality-breaking aura emanated from it. After Goku destroyed one, Beerus summoned dozens at the same time. The energy from that onslaught shook space and the universe’s ability to keep itself together with the same dimension-shattering colors. While the added effect does a lot visually, narratively it does little because Goku’s Super Saiyan God form was still able to vanquish each of the attacks with a super-charged Kamehameha.

Both Goku and Vegeta attain levels of strength far beyond what has been shown so far in Dragon Ball Super: Beerus. Still, even with Mastered Ultra Instinct, Ultra Ego, and Fusion techniques, they would still lose in a fight against the God of Destruction. Beerus is more than 75 million years old and narratively represents a level of power that others can strive to approach but can never attain. If Goku or Vegeta ever did surpass Beerus, the story would lose a large part of its tension and excitement.

Even though Goku & Vegeta's strength has become godly, there are still a handful of Dragon Ball characters they can't & may never be able to defeat.

Several episodes of the new Dragon Ball anime have removed sections of Beerus goofing around in order to make him seem more domineering and even regal. And extra scenes added to his battles have helped make the God even more cocky and cool, specifically his full-body glare and dodging of Goku's attacks on King Kai's planet. But the reality-shaking effect added to his energy balls is a stark reminder that the God of Destruction is too strong, and Dragon Ball Super: Beerus is doing a great job of accomplishing its goal of driving that point across.

Star Trek Officially Restores Seven Of Nine's Humanity In Unimatrix Zero

📅 Nov 11, 2026  |  Category: World  |  Read Source →

Seven of Nine's journey to reclaim her humanity is one of Star Trek: Voyager's most compelling character arcs, and no moment in the series hits quite as hard as the two-part episode "Unimatrix Zero." Although Seven had already been liberated from the Borg Collective, the episode introduced a mysterious sort of virtual sanctuary where certain drones could temporarily escape the hive mind while they regenerated.

Within this hidden world, Seven appeared as Annika Hansen, her original human identity, completely free of the Borg implants that had come to define her appearance. It was an incredible moment for the character, offering a glimpse of the life that had been stolen from her when she was assimilated as a child.

The episode also revealed a forgotten romance from Seven's time in the Collective, further complicating her relationship with her past. Now, more than 25 years later, Star Trek is officially revisiting this pivotal moment in Seven of Nine's story with a brand-new release paying homage to her lost humanity.

Star Trek: Voyager fans are getting an incredible tribute to one of Seven of Nine's most iconic storylines in the upcoming Unimatrix Zero adaptation. The new MTG scene cards recreate the pivotal two-part episode, including Seven's appearance as Annika Hansen, completely free of her Borg implants.

For those unfamiliar, scene cards are special borderless Magic cards featuring interconnected artwork in a grid-style setup. When arranged together, they form a larger mosaic depicting an iconic franchise moment. The Unimatrix Zero scene, illustrated by Gal Or, features six cards arranged vertically, 2-by-3. The full art captures both the threatening Borg Collective and Janeway's efforts to liberate the drones, with Seven's original human form being a great callback for longtime Voyager fans. The six cards are available in non-foil and traditional foil versions through Play Boosters and Collector Boosters. You can take a look at the full mosaic here:

Unimatrix Zero is just one of several incredible scenes included in the crossover. Other Booster scenes include Deep Space Find, which has characters from Deep Space Nine; Mirror, Mirror, which revisits the titular Original Series episode; and Showdown at Sector 001, recreating Picard's assimilation as Locutus. Two additional Scene Boxes, Divergent Timeline and Enterprise-Q, celebrate the Kelvin timeline and Q's memorable encounters with the Enterprise crew, respectively.

With the crossover officially launching on November 13, 2026, anticipation is building among Star Trek fans, particularly collectors eager to get their hands on these stunning tributes to the franchise's history.

Beyond the scene cards, the larger release features Play Boosters, Collector Boosters, specialty bundles, and four dedicated 100-card Commander decks: Federation Fleet, Landing Party, Klingon Fury, and We Are the Borg. These decks spotlight Picard, Spock, Worf, and the Borg Queen, respectively, while bringing numerous familiar characters and starships into Magic's gameplay as well.

Unfortunately, some fans may have to wait a little longer for certain products, as Wizards of the Coast has confirmed production and shipping delays affecting several regions, including North America. Scene Boxes and Bundles are arriving later than originally planned, while Commander decks may miss the November 13 launch.

Draft Night and Beam Me Up Bundles have reportedly also been delayed beyond release day, although Play Boosters remain on schedule. Despite these setbacks, Star Trek and Magic fans are in for an exciting weekend with the official launch on Friday.
