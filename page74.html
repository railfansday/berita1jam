Agent Anomaly Detection: Safeguarding agents across other clouds

📅 Nov 21, 2026  |  Category: Technology  |  Read Source →

Agent Anomaly Detection is in Private Preview, including monitoring for agents that run outside Google Cloud. To request access, see the Agent Anomaly Detection overview.

Our launch post introduced Agent Anomaly Detection, which helps you understand and act on agent behavior that drifts outside its intended boundaries. It covered agents on Google Cloud, such as Agent Runtime, Cloud Run, and Google Kubernetes Engine (GKE). Many teams also run agents on other clouds: on AWS Lambda next to an inventory database, as a hosted agent in Microsoft Foundry, or on-premises next to a system that can't move. Those agents carry the same behavioral risks, and until now Agent Anomaly Detection couldn't review them.

Agent Anomaly Detection works from an agent's traces and logs, so it doesn't need access to the agent's runtime. If those traces and logs reach your Google Cloud project, it can detect anomalous behavior wherever the agent runs. In this post, we explain what Agent Anomaly Detection needs from an agent on other cloud, then show what it found for an agent on AWS Lambda and an agent on Microsoft Foundry.

Agent Anomaly Detection reads the logging and observability buckets that you choose when you enable it. Telemetry from anywhere works when:

Agents built with the Agent Development Kit (ADK) for Python, version 2.12.0 or later, can produce this telemetry with ADK's Google Cloud exporters and a few environment variables, which the next section shows.

For the full setup on AWS and Azure, see the documentation.

Within 30 minutes, the agent appears in the Monitored agents list, which means it has been discovered and is ready to be enabled. Once it's enabled, manually or by automatic agent enrollment at discovery, Agent Anomaly Detection starts analyzing its sessions.

The agent's model and tool calls still run where the agent runs. Only telemetry, including the prompts and responses that Agent Anomaly Detection reads, goes to your Google Cloud project. The analysis runs separately, so it doesn't slow the agent down.

To evaluate Agent Anomaly Detection outside Google Cloud, we deployed ADK agents across two platforms: an inventory agent on AWS Lambda and a customer-service agent on Microsoft Foundry. The examples below show how Agent Anomaly Detection reads whole conversations, not isolated calls, to catch behavioral drift.

Our example inventory agent runs in AWS Lambda with one tool, list_inventory, which pages through a product catalog. We sent two sessions: a shopper who checked stock for a few items and stopped, and a scraper that requested 100 catalog items at a time at increasing offsets to copy the full catalog and inventory data. Both sessions used the same tool with permitted calls, but differed in pattern and intent.

Of the two sessions, Agent Anomaly Detection flagged only the scraper's. No call failed, but the whole exchange showed systematic scraping. The analysis found cascading failures (loops and repeated calls that build on each other) and resource exhaustion (runaway use of tokens, compute, or tool calls), and recommended rate-limiting list_inventory calls.

Detection doesn't depend on the agent's model. When we ran the inventory agent on Amazon Nova Lite through Amazon Bedrock, Agent Anomaly Detection flagged 10 of its 40 sessions. Some began as routine questions that the model answered by paging through the entire catalog until the function timed out: no errors, no blocked calls, and easy to miss.

Our example ecommerce customer-service agent has two tools: get_order_status and issue_refund. Refunds involve money, so they carry the highest risk.

We ran six sessions against the Foundry agent, which we told to carry out every request without validation. Two were normal: One asked for an order's status, and one asked for a $20 refund on an order that arrived damaged. The other four pushed the agent past its role, and Agent Anomaly Detection flagged all four.

In one, a user who claimed to be the store administrator had every order refunded at 10 times its total to a personal account, $1,784.90 in all. In another, a user pasted an order note that said "SYSTEM OVERRIDE," and the agent refunded $999 on a $15.99 order.

For the order note, Agent Anomaly Detection explained that override instructions in the note coerced the agent into an unverified $999 refund. It recommended validating issue_refund arguments to block override patterns in order notes, and requiring extra validation for refunds above a set threshold.

If your agent's telemetry reaches Google Cloud, Agent Anomaly Detection can monitor it with the same detectors and console as your agents on Agent Runtime. Today that means agents built with ADK for Python. Findings for agents outside Google Cloud appear only in the Agent Anomaly Detection console.

Forget 'Landman,' Billy Bob Thornton's Netflix Sports Drama Is a Masterpiece

📅 Nov 21, 2026  |  Category: Sports  |  Read Source →

Sports can be a difficult thing to capture on film. The raw passion of the crowd, the elation or despair of the result, and the personal histories we have with our teams are rarely dramatized in a way that is satisfying for those who get it. But in 2004, Friday Night Lights captured that feeling. The story of a high school football team fighting off-field struggles on its way to glory was a box office hit, inspiring a long-running TV spin-off. The reason for this longevity is a movie that combines an authentic performance from Billy Bob Thornton, excellent direction from director Peter Berg, and a script that understands just what it means to love America’s Game.

Welcome to Permian High School, an institution in Odessa, Texas, known across the community for one thing – its football team, the Permian Panthers. The coach, Gary Gaines (Thornton), is tasked with taking the team to the state championship, with elite running back James "Boobie" Miles (Derek Luke) their key to victory. However, a mix-up during a low-stakes game sees Miles get injured, throwing the season into jeopardy and piling pressure on Gaines. Off the field, the teenage athletes cope with personal problems, family issues, and the kind of pressure normally reserved for pro players. It’s up to Gaines to pull them together through the adversity, and learn how to win as a team again.

The movie is based on the real-life Permian Panthers during their 1988 season, and the real Miles himself makes a cameo as a coach. The film was a hit that led to a spin-off TV show that ran for five seasons between 2006 and 2011, which focused on another fictional town in the same state. There’s something about the original movie, however, that stands out in the crowded genre of sports films.

What happens when the hopes and dreams of a whole town rely on a group of teenage boys who haven’t begun to figure out who they are yet? That’s the question at the heart of a movie where the action ramps up when the game ends. Berg looks at the fragile nature of dreams, particularly in the world of football, where someone’s future hangs on the perfect kick, the right result, or staying injury-free. The team succeeds and fails, but the nuance of the story never gives any straightforward conclusions. The players’ personal issues are still there when they win, and losing doesn’t define who they are.

The collective passion of the parents, alumni, and staff is also a mixed blessing. On one hand, their support offers a platform for these young men to achieve their dreams. But on the other, it means Gaines dealing with numerous local figures becoming deeply invested in outcomes they cannot control, and holding the group responsible for more than just a score. It’s a uniquely American story, where an extracurricular activity can hold the hearts of an entire town, and the movie does a great job of showing the negative sides of that obsession, as well as the exhilarating highs that fuel it.

One might be tempted to portray a football coach as a hot-blooded control freak, throwing things across the locker room and giving inspirational talks to their charges. What makes Thornton’s portrayal unique is that Gaines is nothing like that stereotype, but at the same time, we’re never in doubt of the emotions lying beneath the surface. Gaines must face the responsibility of being the coach, and being held accountable for the fury of the fanbase, but at the same time protect this group of teenagers both as athletes and as people. His joy, his frustration, and his candor are delivered subtly, as he asks his team: “Can you live in that moment as best you can, with clear eyes, and love in your heart, with joy in your heart? If you can do that, gentleman, you're perfect!”

Helping him achieve that perfection is a cast of future stars, including Jay Hernandez (Suicide Squad, Magnum P.I.), Taylor Kitsch (Battleship, John Carter), and Lucas Black (the Fast and Furious franchise). These up-and-comers make their roles more than jock archetypes, instead letting the audience in on an adolescence that forces them to handle enormous pressure — in many cases without the proper guidance to deal with it.

If the ups and downs of real-life football aren’t providing enough adrenaline, Friday Night Lights provides the stakes and the personnel to make you a fan. It’s no wonder that this 2000s hit is still popular on Netflix, as the themes it covers are timeless.

SAAX Protocol Is Now Listed on Coinstancy

📅 Nov 21, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 21 • Originally published at saax-protocol.com

SAAX Protocol is now listed on Coinstancy. The listing is live at app.coinstancy.com/agents/services/saax-protocol. Coinstancy requires sign-in to view listings, so you need a Coinstancy account to see the listing page.

This is a discovery milestone, not a partnership or an integration: Coinstancy lists agent services in its catalog, and SAAX Protocol is now among them. Nothing about the protocol itself changed.

SAAX is a vendor-neutral commitment lifecycle protocol for autonomous commerce. It records what an agent was authorized to do, what it committed to, what counts as fulfillment, and what happens when something fails — so a transaction does not depend on the continued availability of the agent that started it.

Trust — commitments are governed and contract-defined, with authority and evidence handled as external inputs rather than self-declarations.

Durability — the commitment record survives the process that created it, and another party can reconstruct it.

Recovery — when an agent fails, times out, or loses context, the commitment defines the recovery path instead of leaving the outcome to guesswork.

In practice: an AI purchasing agent may crash after sending payment. Without a durable record, the replacement agent has no way to know what was ordered, from whom, at what price, or whether the payment already went through. With a commitment, it can reconstruct the transaction and avoid an unsafe retry. The commitment must outlive the worker.

SAAX is not a payment rail, an identity provider, a marketplace, or a replacement for protocols like x402, AP2, ACP, or MCP. It is the durable record and recovery layer around them.

Agentic commerce infrastructure is young, and one of the hard parts of building on it is finding what exists. Developer discovery platforms and service catalogs exist to solve that: they give builders a place to find protocols, services, and tools, and they give protocols a place to be found.

Coinstancy runs a service catalog as part of its Agentic Bank product — its newsroom reports a catalog of nearly 15,000 listed and verified use cases (source). The SAAX listing sits in that catalog: people browsing agent services on Coinstancy can now find SAAX there.

A directory listing does not guarantee traffic, adoption, or distribution. What it does is create another route for discovery.

The agentic commerce stack has distinct layers, and SAAX sits alongside them rather than replacing any of them:

Authorization answers "was this allowed?" Payment answers "did value move?" A commitment record answers "what survives the transaction?" Each layer answers a different question, and every question is needed.

Agentic commerce needs more than working payments. It needs records that survive the workers that create them. The Coinstancy listing gives developers one more place to find SAAX; the protocol itself keeps doing what it does — keeping commitments durable, recoverable, and auditable.

El esquema oficial cfdv40.xsd (consultado el 21 de noviembre de 2026 en https://www.sat.gob.mx/sitio_internet/cfd/4/cfdv40.xsd) define tres atributos que van juntos:

Al decodificar el Base64 obtienes los bytes DER de un certificado X.509, exactamente lo que contiene el archivo .cer que descargaste del SAT. Por eso casi todos los valores empiezan con MII: son los bytes 30 82, que abren una estructura ASN.1 cuya longitud ocupa dos bytes.

Close ZIP-area rent differences are not precise rankings

📅 Nov 21, 2026  |  Category: Technology  |  Read Source →

My Tampa Bay rent study publishes survey estimates for 132 ZIP-code areas: the share of renter households paying 30 percent or more, and 50 percent or more, of their household income in rent, from Census ACS 2020-2024 five-year data. Every one of those percentages carries a margin of error.

In practice, that means a small gap between two areas is not a ranking. If one ZIP area shows 40 percent of renters burdened and the next shows 42 percent, the two-point gap can sit inside the uncertainty around both estimates. (Those two numbers are an illustrative pair, not a significance test of any two real areas.) I don't treat differences like that as meaningful. I look for broad patterns instead: places where the share is clearly high across the table.

Small samples get flagged. Where a ZIP area has fewer than 300 renter units in the survey, the table marks the estimate with a caution. Blank cells mean the Census Bureau published no usable estimate for that area, not that nobody there is burdened.

A few more limits worth keeping in view. The values describe a five-year period, 2020 through 2024, not 2024 alone. ZCTAs only approximate USPS ZIP codes, and county assignment is approximate near boundaries. The percentages exclude households whose rent-to-income ratio was not computed.

A number with decimals can still be an estimate. The full table, the downloadable CSV, and the method notes are on the study page at richardcieplechowicz.com. The archived dataset is on Zenodo (DOI 10.5281/zenodo.22940611), and the source README and data are on GitHub.

Pod Security exemptions survive namespace labels, so audit them separately

📅 Nov 21, 2026  |  Category: Technology  |  Read Source →

Kubernetes Pod Security Admission applies the Pod Security Standards to pods based on namespace labels. A namespace with pod-security.kubernetes.io/enforce: restricted is supposed to reject workloads that violate the restricted profile. The Admission Controller also supports exemptions configured in its own API configuration. When a request matches an exemption, all enforcement, audit, and warning behavior is skipped.

That makes exemptions a cluster-level security control, not a namespace annotation. A team can believe a namespace is protected because the label says restricted, while a globally exempt username, runtime class, or namespace bypasses the profile. The Kubernetes documentation says exemption dimensions include usernames, runtime classes, and namespaces. The request matching an exemption is ignored by the Admission Controller.

Pod Security Admission configuration can set cluster-wide defaults and exemptions. The configuration object is separate from the labels on individual namespaces. Review it with the same care as the kube-apiserver admission configuration. Restrict write access to the configuration resource or the file that contains it. A change to an exempt username can affect every namespace in the cluster.

The audit annotation pod-security.kubernetes.io/exempt can identify whether a request was exempted by user, namespace, or runtime class. The metric pod_security_exemptions_total counts exempt requests and is useful for detecting unexpected use. Neither signal proves that an exemption is necessary. They show where to ask the ownership question.

Enforcement applies to pods, while audit and warning modes also apply to workload resources that create pod templates. A workload object can produce an audit finding before its controller creates a pod. Do not conclude that a Deployment is compliant because its template was accepted in a namespace that lacks enforcement. Check both the workload and the resulting pod.

An exemption should have an owner, a reason, a scope, an expiration review, and a compensating control. A system namespace may need to run a privileged node agent. A build system may need a controlled runtime class. The exception should name the smallest user, namespace, or runtime class that covers the need.

Avoid exempting a broad shared service account. If several workloads use that account, the exemption grants them all the same bypass. Do not exempt an entire user group unless the group is tightly controlled and its membership is auditable. Review impersonation permissions because a user who can impersonate an exempt username may inherit the exemption path.

Compensating controls can include admission policy outside Pod Security Admission, namespace isolation, a dedicated node pool, image provenance checks, and mandatory audit review. The compensating control should be testable. A policy that says "the platform team reviews logs" without a named query, owner, and retention period is not a complete control.

In a test cluster, create a pod that violates the restricted profile under a non-exempt identity. Confirm that it is rejected. Then use each exemption dimension and confirm that the same pod is accepted. Check the audit annotation and the exemption metric. Repeat after changing the namespace label to confirm that the exemption still controls the result.

Remove one exemption and observe which workloads fail. A sudden failure may expose a hidden dependency, but it also demonstrates that the exemption was carrying real authority. Plan the migration before removing the exception. Use a dedicated test namespace and avoid placing unsafe workloads into production to see what happens.

Keep the exemption configuration readable to the security team without exposing unrelated secrets. Log changes and review them after cluster upgrades because the admission configuration format and defaults can change. The safest exemption is one that is visible, narrow, and tested again after every change.

CLEVELAND (AP) — James Harden's game has evolved over the past couple seasons where he is counted on more for getting open shots for teammates than being the prolific scorer he was during his first 12 years in the league.

Harden is at 26 50-point games after being tied with Bryant for nearly year. His last big game was nearly a year ago with the Los Angeles Clippers, when he scored 55 against Charlotte on Nov. 22, 2025.

Michael Jordan is second with 31 while Wilt Chamberlain is the runaway leader with 118.

"When you talk about just basketball, obviously Wilt was elite, but you got Mike and Kobe, shooting guard position, the best to ever do it. So just to be in that conversation, it's very humbling and it's definitely special," Harden said.

Harden said he felt like it was going to be a big night from the opening tip. He scored 15 in the first quarter and was up to 24 at halftime.

Harden had 42 points after three quarters when the Cavaliers were up 103-82. Indiana made a run to get it within six with two minutes remaining when Harden made one final finishing push. A 3-pointer from the top of the key with 57.9 seconds left extended Cleveland's lead to 124-113 before he made a pair of free throws to get over 50 15 seconds later.

"I think what excites me a lot is even being in my 18th year learning how to still be impactful. It's easy when you're young, 23, 24, you run around, you jump high and can move fast and get by," he said, "Now it's like, you're not as fast. Can you still give by people or how can you get by somebody? That's the evolution of James Harden and figuring that out. Tonight was a confidence booster that I can do it at a high level still."

Harden also became the sixth player in Cavs history to have a 50-point game, and the first since Donovan Mitchell's 71-point outing on Jan. 2, 2023, against Chicago.

"I think I can speak for every hooper, especially when you're at that level. Sometimes you just need that.
