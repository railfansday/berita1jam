SQLPad admin and service tokens concentrate database reach

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

A SQL console can be more sensitive than the databases it reaches. SQLPad stores connection definitions and lets users run queries, while administrators can manage users and connections [1]. A service token created by an administrator can turn a browser convenience into a durable API credential with broad database reach.

SQLPad supports local authentication with email and password by default. Passwords are stored in its embedded database using bcrypt hashing. The initial administrator is configured through SQLPAD_ADMIN, optionally with SQLPAD_ADMIN_PASSWORD, and additional users are added by an administrator [1].

The application has two roles today, Admin and Editor. An administrator can add or edit database connections and create users. The configuration documentation says service tokens are generated by logging in as an admin and using the Service Tokens page [2]. Those tokens deserve separate review because they may outlive a browser session and are intended for automation.

I ran three count-only probes on 2026-11-09 with sub_type=all, page 1, and page size 1. The application-fingerprint query app="SQLPad" matched 1,067. The title query title="SQLPad" matched 1,022. A body query http.body="SQLPad" matched 1,084.

The three counts are close, which is useful but not proof that every match is a working SQLPad instance. The app fingerprint is the strongest discovery signal in this run. The count still does not show whether authentication is enabled, which databases are connected, or who holds a service token.

Inventory every connection, its database role, network path, and owner. A SQLPad administrator may be able to edit a connection string even if they do not know the database password. The connection can use a privileged database account, so SQLPad's own role check is not the only authorization layer.

Prefer a dedicated read-only database account for analytic work. Use a separate connection for a job that needs writes. Do not let an Editor share a connection whose credentials can modify every tenant. Query-level controls, database roles, and row-level policies should remain in force.

Review the SQLPAD_USERPASS_AUTH_DISABLED and default-role settings. The documentation warns that disabling local user-password authentication can require a default role for users from another identity source [1]. A misconfigured default of Admin turns authentication success into administrative authority.

The API overview documents HTML Basic authentication for users and password access unless local authentication is disabled. Service tokens are a separate mechanism. Keep tokens in a secret manager, scope each one to a dedicated operator, and record the purpose and owner.

Test the API with a token that should be denied. Confirm that the denial is enforced by SQLPad and by the database account, not only by the UI. Review token creation and last-use records. Revoke stale tokens after integration or staff changes.

Restrict the web and API paths to a management network or a reverse proxy with strong authentication. Require TLS. Protect the embedded database because it contains password hashes, connections, and session state. Back it up with encryption and restrict restore access.

Log user, connection, query identifier, row count, and result status without storing the query text or returned data in an exposed log. Alert on queries that read unusually large volumes, connection changes, new administrators, and service-token creation.

If an administrator account is compromised, disable it, revoke its sessions and service tokens, and review connection changes. Determine which database credentials were visible and rotate them. Review the databases' own audit logs because SQLPad may not record every statement or data access.

The external SQLPad count is a discovery metric. It does not say whether a console is internet-facing, which databases are connected, or whether a token has broad authority. Review those facts at the owner, then use the count to organize outreach and follow-up.

SteamVR vient de rendre la VR plus nette. Voici ce que j'y mettrais.

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Cette semaine, Valve a publié une mise à jour bêta de SteamVR qui améliore la qualité d'image transmise à tous les casques autonomes compatibles Steam Link : Meta Quest, HTC Vive Focus, PICO. Steam Link, c'est l'application de streaming de SteamVR — celle qui fait tourner votre bibliothèque Steam sans fil sur un casque autonome. La nouveauté porte sur la netteté du flux.

Vous me direz : encore une note de version. Sauf que cette note touche exactement le point qui bloquait un usage de la VR dont on parle peu.

Depuis des années, la VR se vend comme un média de jeu. Pendant ce temps, une petite communauté l'utilise pour regarder des molécules. Et cette communauté butte sur un problème très concret : lire des détails fins dans un casque. Une hélice alpha, un feuillet bêta, une chaîne latérale qui pointe vers un ligand — ce sont des objets de quelques ångströms. Si le rendu n'est pas net, la structure devient une masse colorée.

C'est un problème de pipeline, pas de puissance brute. Un flux Steam Link, c'est une chaîne : rendu côté PC, encodage, transport réseau, décodage dans le casque, reprojection. Chaque maillon ajoute sa perte. La compression vidéo lisse les arêtes fines. Le sous-échantillonnage chromatique bave sur les lignes de 1 à 2 pixels. Et une liaison peptidique, dans un rendu cartoon à distance de lecture, c'est souvent une ligne de 1 à 2 pixels. Ajoutez le mouvement de tête et la reprojection : les atomes se dédoublent dès que vous tournez.

Rien de tout cela n'est propre à la biologie structurale. Mais c'est là que ça fait le plus mal, parce que la donnée elle-même est dense. Un fichier PDB courant, c'est des milliers d'atomes, des milliers de liaisons, des feuillets superposés sur quelques ångströms de profondeur. Sur un écran 2D, on zoome et on tourne avec la souris. Dans un casque, on tourne la tête — et si l'image n'est pas stable, le cerveau décroche. La charge cognitive part dans la reconstruction de l'image au lieu de la compréhension de la structure.

Chaque amélioration de la qualité d'image rend donc une question plus crédible : et si le bon contenu pour un casque n'était pas un jeu ?

NexoPeek est un laboratoire moléculaire VR pour Meta Quest. Trois couches.

Les visites guidées. 12 visites narrées sur 6 piliers : Biotechnologie de base, Fondements de la vie, Voies et interactions, Médicaments en action, Technologies génétiques, Biotech verte. On entre dans l'hémoglobine pour voir l'oxygène se fixer. On suit le glucose qui se décompose dans la glycolyse. On regarde l'aspirine bloquer les enzymes COX. On assiste à CRISPR-Cas9 qui édite l'ADN.

Le lecteur PDB professionnel. Une recherche intelligente qui résout un nom de gène sur RCSB PDB, UniProtKB, AlphaFold DB, SWISS-MODEL et PDBe, et charge la structure à taille humaine. Les presets Mol* se déclenchent en un geste : cartoon, ball-and-stick, spacefill CPK, surface moléculaire, carte de facteur B, tracé en tube. Les fichiers locaux (.pdb, .cif, .mol2) s'ouvrent avec cartes de champ électrostatique et volumes de densité électronique.

Le banc d'analyse. Attraper, mettre à l'échelle, faire tourner la molécule à mains nues ou aux manettes. La prédiction de poches par IA met en évidence un site druggable (PrankWeb / P2Rank, cloud ou moteur hors ligne). Foldseek superpose un homologue. L'inspecteur de ligands trace les liaisons hydrogène et va chercher un ligand 3D dans PubChem. Deux atomes piqués, et la distance en ångströms s'affiche. Les pastilles de résidus touchées dans la séquence projettent un halo 3D sur la structure.

Et le mode Room View fait flotter la molécule dans votre pièce, menu mural toujours opérationnel.

Deux choix valent d'être explicités, parce qu'ils sont discutables.

Le premier : la recherche fédérée. On ne stocke pas de base locale. On interroge RCSB PDB, UniProtKB, AlphaFold DB, SWISS-MODEL et PDBe, puis on résout un nom de gène vers un identifiant de structure. Le compromis est clair — on dépend du réseau et des quotas des API publiques, mais on hérite de bases maintenues par d'autres, et on ne se retrouve jamais avec une copie périmée. Pour un outil éducatif, c'est le bon arbitrage.

Le deuxième : les presets de rendu. Mol* est puissant, mais sa surface d'API est large. On a préféré exposer des presets à un geste — cartoon, ball-and-stick, spacefill CPK, surface, carte de facteur B, tube — plutôt qu'un panneau de réglages complet. C'est une concession : on perd en expressivité ce qu'on gagne en accessibilité. Pour le public visé, ça se défend.

Côté analyse, la prédiction de poches tourne soit dans le cloud, soit sur un moteur hors ligne. Le mode hors ligne existe pour les environnements sans réseau fiable — salles de cours, labos cloisonnés. Là encore, un arbitrage : moins de modèles disponibles, mais aucune dépendance externe.

Un point sur lequel je n'ai pas de chiffres honnêtes à donner : le gain réel de la mise à jour SteamVR sur une session NexoPeek. Je n'ai pas fait de banc d'essai contrôlé, et je ne vais pas inventer un pourcentage. Ce que je peux dire, c'est que la netteté du flux est le facteur limitant côté casque autonome, et que toute amélioration de ce maillon se ressent d'abord sur les contenus denses en détails fins. La biologie structurale en fait partie.

Parce que l'actualité SteamVR n'est pas un argument de vente — c'est un signal. La VR grand public améliore lentement ce qui comptait le plus pour un usage scientifique : la fidélité visuelle. De l'autre côté, la biologie structurale produit des volumes de données que personne ne peut vraiment lire en 2D.

Ces deux courbes se rapprochent. Je pense que ça vaut la peine de le regarder de près.

RTC Room Tokens Explained: 6 Identity and Permission Controls for Healthtech

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

A patient-call notification is useful only if the intended clinician can join the intended room with the intended powers. Short answer: a room token carries the room name, participant identity, and permissions; mint it on the server, because the client must not get to rewrite those claims. Treat a permission change as a new-token event, not a UI toggle.

For in-app healthtech notifications without polling, the hard problem is not making a badge appear. It is preserving that authorization decision while the event fans out, retries occur, and a call artefact moves into private storage. I use six controls for that boundary. They are deliberately boring. Missed jobs and duplicate deliveries have made me suspicious of clever queue paths.

Infrai fits one specific part of this design: issuing the RTC credential and keeping the resulting private artefact under the same API key and REST contract. Pusher, Ably, and PubNub are worth evaluating for the notification fan-out itself; LiveKit, Daily, Twilio Video, and Agora are specialist RTC comparisons.

A useful room token answers three questions: which room, which participant, and which actions. The room binds the credential to one call. Identity gives moderation and audit records a stable subject. Permissions decide what that subject may do.

Suppose a care coordinator receives an event for room consult-4821. The browser may display a Join button, but that button is not authority. A modified client cannot bypass permissions carried by the server-minted token.

Never mint this credential in the browser or mobile app. The application server authenticates the user, evaluates the current role, and issues the room token. Do not put clinical notes, diagnosis text, or unrelated patient data into it. None is needed to answer the three authorization questions.

Because a client-side flag is presentation state, not an authorization grant. If a nurse becomes moderator for an escalated call, the server should evaluate that change and issue a new token with the new permissions. The old token does not become stronger because the UI changed.

Identity is also the join point for operations. A kick action has meaning only when logs and moderation refer to the same participant identity that was authorized to enter. Without that invariant, an incident timeline degenerates into device IDs and display names that an accidental reconnect can change.

There is a second invariant: retries must not create two logical participants or two notifications. The fan-out transport may redeliver. Consumers should process an event ID once, and joining should retain the authenticated participant identity rather than generate a fresh identity on every attempt. Assume at-least-once delivery at the application edge. It produces a safer design even when one component offers stronger guarantees.

Push the in-app notification after the server has made the access decision, and include an opaque event ID plus the room reference the recipient needs. Do not send a reusable privileged token through a broad notification payload. Fetch or issue the room token at the authenticated join boundary.

That order closes a common race: notification first, authorization later. A role can change between alert and join while the client continues with stale assumptions. Server issuance turns the latest decision into the credential. If permissions change again, issue another token.

My first instinct in queue systems is to make the publisher responsible for exactly one delivery. That is the wrong place to spend confidence. Networks time out after a write, workers restart after a side effect, and acknowledgements disappear. The practical control is an idempotency key at publication plus an inbox record at consumption. Key that record by event_id + recipient_id; after its transaction commits, a duplicate becomes a no-op.

Consider the ugly sequence rather than the happy path. The server authorizes clinician-73, publishes event evt-884, and times out before it sees the acknowledgement. It publishes again. One worker writes the inbox row and sends the in-app signal, then crashes; another worker receives the duplicate. A unique key on evt-884 + clinician-73 makes the second transaction harmless. When the clinician taps Join, the server checks the current role and issues the token then, so a role revoked between notification and join cannot ride on stale client state. No promise of exactly-once transport is needed. The database invariant carries the load.

The contracts differ. The event says, "there is a call for you." The token says, "this authenticated participant may enter this room and perform these actions."

A call may produce a consent document, transcript export, or recording reference. The useful integration boundary is the handoff from the authorized session to a bucket the application controls.

Infrai is a concrete fit when a team wants RTC room tokens and private object storage behind the same API key and base URL. Swapping the provider behind a capability does not require the application contract to move with it. Its public discovery response exposes each capability's method, path, request JSON Schema, response schema, billing data, and runnable examples, so a Go client can validate the live contract instead of copying an SDK-specific request type. The platform reports 295 routes across 20 modules, with documented capabilities represented by runnable examples in ten languages.

I recommend trying Infrai for the token-to-private-bucket boundary when a small platform team wants less credential sprawl while keeping server-side identity and permission checks in its own code. That is narrower than recommending it for every media system, and it is where a stable REST contract removes concrete integration work.

This runnable guard verifies the two published routes, proves that one key and base URL select both capabilities, and feeds the authorized room handoff into a private artefact bucket name. It does not invent request fields: the live JSON Schemas remain authoritative.

Actual create calls generated from those schemas should use Authorization: Bearer $INFRAI_API_KEY, send an explicit POST, check every response status, and attach an idempotency key to writes. Storage stays private or signed-only. A presigned upload or download URL must not receive the Infrai authorization header.

One caveat deserves a plain sentence: consolidation means one vendor to trust, one bill, and one outage surface.

For this workflow, LiveKit plus S3 or Daily plus S3 means two signups, two credential sets, two API surfaces, and glue that maps an authorized room session to a private object location. That separation may be desirable. It also has a cost.

Ask who owns token semantics, how credentials rotate, where idempotency lives, and how an operator traces event_id from notification to join to artefact. Pusher, Ably, and PubNub compete at the event-delivery layer, not as substitutes for an RTC room token or private object storage; choosing one still leaves those two contracts to integrate. A plain REST surface shortens first use because there is no capability-specific SDK to install; public discovery makes the request contract inspectable without a key. Separate specialists give each domain an independent failure boundary and may expose deeper media controls.

Choose the specialist when its media behavior is the requirement. If the product needs provider-specific RTC features beyond room identity, participant permissions, moderation, and the verified routes, evaluate LiveKit, Daily, Twilio Video, or Agora on those exact features. Existing S3 governance or organizational policy can likewise outweigh one credential.

Before shipping, test a viewer token against a publisher action and expect denial. Change a participant's role, confirm that the old token does not gain permission, then issue a new one. Replay the same notification twice and confirm one user-visible result. Kick a participant and verify that the audit record uses the identity from the authorization decision. Finally, trace the call's opaque room reference into a private artefact location without placing patient data in a bucket name.

Keep rollback dull. Stop new notification publication, preserve idempotency records, revoke or expire access through the supported token lifecycle, and retain the correlation IDs needed to explain what happened. Do not repair an authorization incident with client flags.

The rule fits on one line: mint identity and permissions on the server, treat fan-out as replayable, and carry only the minimum stable reference into private storage. If that boundary fits your system, start with the Infrai documentation and inspect live discovery before writing a request.

In a modeled doubling of XRP, a $10,000 XRP–RLUSD pool position reaches about $14,142 versus $20,000 from simply holding XRP, before fees and costs.

The XRP Ledger pool pairing XRP with Ripple’s dollar stablecoin, RLUSD, quotes about 4.7% annualized trading-fee yield. Joining this native pool changes what an XRP holder owns. The position becomes a shifting mix of XRP and the dollar stablecoin, surrendering some exposure to a rebound while cushioning some of a decline.

Those figures are estimates, not a reconstruction of fees actually earned throughout the week. Under the XRPL’s constant-product mechanics, trading changes the XRP and RLUSD quantities represented by liquidity-provider tokens. Fees accumulate inside the pool and become part of the assets those LP tokens can redeem.

Two comparisons are therefore needed. Holding everything in XRP preserves full XRP price exposure. Leaving an initial 50/50 XRP–RLUSD allocation untouched starts with the same asset mix as the pool but avoids its automatic rebalancing.

Consider equal $10,000 starting investments. In a hypothetical model with RLUSD fixed at $1, no fees or costs, and the pool adjusting to XRP’s new relative price, a 20% XRP rise leaves the pool worth about $10,954. Untouched 50/50 holdings reach $11,000; an all-XRP holding reaches $12,000.

Most of the gap to all-XRP comes from choosing stablecoin exposure in the first place. The smaller gap to untouched 50/50 holdings isolates the rebalancing shortfall commonly called impermanent loss.

The downside comparison changes the conclusion. With XRP down 20%, the modeled pool is worth about $8,944, versus $9,000 for untouched 50/50 holdings and $8,000 for all-XRP. The pool still loses money, but retains more value than the fully exposed XRP position.

Warren Buffett Has 1 Simple Rule for Surviving a Stock Market Crash, and History Says It's Never Once Failed

If a bear market is coming, Warren Buffett's advice is more important than ever.

It's been a roller-coaster of a week for the stock market. The Nasdaq Composite (^IXIC +1.09%) officially entered correction territory after falling by more than 10% from its October peak, while the S&P 500 (^GSPC +0.31%) and Dow Jones Industrial Average (^DJI -0.46%) are down by around 6% and 5%, respectively.

Investors are also grappling with the downturn. The Fear and Greed index measures investor sentiment based on multiple stock market metrics, and it quickly plunged into the "extreme fear" category amid this week's turbulence.

But it's not all bad news right now. Warren Buffett has some timeless advice for investing during crashes and bear markets, and history says this strategy has worked out every single time.

When the market is shaky, it can be tempting to avoid investing or even sell your stocks in fear that prices will fall further. According to Warren Buffett, though, that's one of the worst moves to make during a slump.

"A simple rule dictates my buying," Buffett explained in a 2008 opinion piece for The New York Times. "Be fearful when others are greedy, and be greedy when others are fearful." He went on to emphasize that "bad news is an investor's best friend. It lets you buy a slice of America's future at a marked-down price." In other words, when the future is bleak, buy more.

In the years following the publication of that piece, the S&P 500 soared by nearly 1,000%, and the investors who reaped the biggest rewards were those who stayed invested even when it was tough.

"Over the long term, the stock market news will be good," Buffett continued, noting the Dow's extraordinary rise from 66 to 11,497 during the 20th century.

"You might think it would have been impossible for an investor to lose money during a century marked by such an extraordinary gain. But some investors did. The hapless ones bought stocks only when they felt comfort in doing so and then proceeded to sell when the headlines made them queasy."

No matter how severe the short-term volatility is, the market has always managed to recover.

During the dot-com bubble in 2000, for example, the S&P 500 fell by nearly 50% as the tech sector collapsed. It took until 2007 for the index to reach another all-time high, and just a few months later, the Great Recession began.

However, between 2000 and 2020, the S&P 500 still earned total returns of more than 224%. In other words, even if you'd invested at seemingly the worst moment -- immediately before the onset of two of the worst recessions in U.S. history -- you'd still have more than tripled your money over 20 years.

This trend holds up throughout history, too. Between 1919 and 2025, all of the S&P 500's rolling 20-year periods have ended in positive total returns, according to analysis from Crestmont Research. By holding an S&P 500 ETF or index fund for 20 years, it's historically been harder to lose money in the stock market than to make money.

Regardless of what's ahead for the market, continuing to invest is key. However, it's more important than ever to choose your stocks wisely. Weak companies can thrive during periods of economic prosperity, but recessions and bear markets will hit those stocks the hardest. The weakest of them may crash and never recover at all.

Companies with strong fundamentals -- such as a durable competitive advantage, healthy finances, and a competent leadership team -- are the most likely to rebound after a crash. The more of these stocks you own, the better prepared you'll be to not only survive a downturn, but thrive over time.

At what length do DisplayPort cables start giving you trouble?

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

The longer a DisplayPort cable gets, the lower the visual quality will become

Although pure USB-C and Thunderbolt video connections are gaining traction, DisplayPort continues to rule the day for a lot of Mac and Windows PCs, and it's likely just as much about production cost as legacy compatibility. To equal the bandwidth of the best DisplayPort tech, companies need to use USB 4 v2 or Thunderbolt 5. Whether that's inherently more expensive to manufacture or not, people also tend to expect power delivery through USB-C and Thunderbolt, whereas DisplayPort can be exclusively about video.

A major concern with any video format is how far a clean signal can be delivered. With HDMI, for example, connections can get sketchy past 25 feet, if not far earlier. When a cable isn't up to the job, the result can be problems like artifacts, flickering or connections dropping out entirely. Alternately, a display might automatically scale back resolutions and refresh rates.

With DisplayPort, the limitations can be pretty sharp if you want to maintain maximum quality. There are ways around them, but they're probably not worth the money for most computing setups.

The standard copper-based DisplayPort cable should be solid up to 6 feet. By solid, we mean capable of displaying any resolution, color or refresh rate combo you could realistically ask for, such as 4K HDR at 144Hz. You shouldn't experience artifacts or other issues with this setup, barring physical damage or severe interference that would probably affect the rest of your hardware too.

By about 10 feet, resolution and refresh compromises begin to enter the picture. 4K refresh rates may be limited, or else resolution could be forced to drop to 1080 or 1440p. Toward 15 feet, stable 4K is gone and even those lower resolutions might be capped at slower refresh rates.

Luckily, that's not the true limit of DisplayPort. What we've been talking about so far is the performance of passive copper. If you switch to active copper cables that boost signal strength, practical range can extend to between 15 and 30 feet. Even better are fiber optic cables, which can run up to 100 feet.

Expect to pay for the privilege, mind you. Whereas a 10-foot passive copper cable (rated for DisplayPort 2.1) can cost as little as $10, even a 15-foot fiber optic cable can cost north of $50. That second cable should be bulletproof, but it's probably not worth the investment outside of corporate offices.

Most people should stick with passive copper DisplayPort cables measuring 6 feet or less. Although active copper and fiber optic cables provide reliable performance at greater distances, there's usually no need for it since DisplayPort is almost exclusively associated with monitors. If a monitor is sitting on your desk, it's almost certainly less than 6 feet away from your computer.

In fact, if you're daisy-chaining monitors via MST (Multi-Stream Transport), it's better to stick to the shortest cables possible since two 3-foot cables already brings you up to the 6-foot mark. It's all too easy to accidentally cripple one of your screens even if the GPU in your computer is likely going to be the biggest bottleneck. You need powerful hardware to run 4K games at 120Hz on a single screen, let alone two. The requirements soften for most productivity apps, yet the general concern remains.

It'll be interesting to see how much longer DisplayPort hangs around as a separate cable format. Once costs come down and devices are equipped with USB 4 v2 and Thunderbolt 5 as a matter of course, there may not be any incentive to keep DisplayPort in the mix. Not when port space is already at a premium.

TL;DR: FinCEN and the Federal Reserve are withdrawing a proposed expansion of US recordkeeping and Travel Rule requirements that would have covered certain convertible virtual currency transfers and lowered a cross-border transfer threshold. The withdrawal removes a proposal; it does not cancel existing anti-money-laundering obligations.

Two announcements issued by the same US agency on November 6 point in different regulatory directions. While FinCEN imposed a targeted financial restriction on MEXC Global, it also announced that it was withdrawing a previously proposed update to the Recordkeeping and Travel Rule for funds transfers.

According to FinCEN’s release, the proposal would have amended requirements relating to convertible virtual currencies and certain digital assets. It would also have lowered a threshold for transfers beginning or ending outside the United States. The Federal Reserve Board joined the withdrawal.

This distinction is central to understanding the announcement. A proposal describes changes regulators are considering. Withdrawing it means those proposed changes will not proceed through that rulemaking in their existing form. It does not mean every reporting, customer-identification or information-sharing requirement currently applying to financial institutions has disappeared.

The Travel Rule generally addresses information that financial institutions must collect or transmit when handling covered transfers. In the digital asset industry, implementation raises difficult questions about service-provider identities, unhosted wallets and transfers that cross multiple systems. A proposed amendment can change where those obligations attach or what thresholds apply, but it cannot be read as the whole compliance framework.

FinCEN explicitly frames this action as the withdrawal of a notice of proposed rulemaking. Companies should therefore update regulatory trackers and comment schedules without treating it as permission to suspend controls that already exist under separate law.

Rules governing transfer information affect the customer experience as well as the institution behind it. More extensive data-collection requirements can add operational cost, create friction during international payments and complicate relationships between banks and crypto businesses. Supporters of stricter rules argue that traceability is needed to investigate laundering and sanctions evasion; opponents can point to privacy, proportionality and practical implementation burdens.

The November announcement does not settle that debate. It signals that the agencies have chosen not to move ahead with this particular expansion. A future rulemaking or different targeted action remains possible, and the exact scope of any later proposal cannot be inferred now.

That sits beside FinCEN’s much harder action against MEXC: the agency can withdraw a broad proposal while using existing powers against entities it believes pose specific risks. The two decisions are not mutually exclusive.

Banks, exchanges and payment providers should review the published withdrawal documents, identify which previously planned systems changes relied on the abandoned proposal, and keep existing transfer-screening arrangements in place unless their legal teams determine otherwise. Cross-border businesses should pay particular attention to the difference between US requirements and rules in the jurisdictions where counterparties operate.

For a while, one of the most reliable relationships in my life was with a traffic sign.

It was one of those electronic billboards you see on the outskirts of villages that nags you for how fast you're driving. Go too fast and the numbers flash red. Keep to the speed limit and you're rewarded with two words of appreciation:

I became a bit too fond of that sign. Embarrassingly, some days I would deliberately crawl past it, making sure I was going at exactly the right speed, just to receive its validation. And it delivered. Every time.

“You're most welcome,” I'd think, feeling absurdly pleased with myself.

Now, you might reasonably wonder why a mature woman would get quite so much satisfaction from being thanked by an illuminated slab of roadside equipment.

I'd recently returned from Switzerland, and was trying to find my feet in a community where I'd once felt very much at home. Much had changed in my absence, and cultivating a sense of belonging was proving difficult.

I was living alone, feeling bereft, and some days the only living creature I spoke to was an elderly cat. Not to be too judgy, but although he was selectively affectionate, his vocabulary wasn’t up to much. So the traffic sign became an accidental but welcome addition to my social circle.

I knew perfectly well that it was only thanking me for driving at the appropriate speed, but I looked forward to those two little words dropping into my day. It felt good to be acknowledged and, truthfully, I wanted some reassurance that I hadn't disappeared.

I've been reflecting on that period recently, and about how much we rely on other people to remind us who we are. It's a backdrop we barely notice when life is flowing along reasonably well. We have our familiar routines, people to talk to, and places to go. There's a sense of belonging that we probably take for granted until our circumstances change.

I think this is one of the reasons loneliness can be so unsettling. Alongside the sadness of having nobody to share things with, there's the strange experience of chalking up an entire day without anyone witnessing it.

You might have achieved something substantial, or white-knuckled your way through a thoroughly miserable morning. Maybe you made a particularly earthy soup with the leeks from your garden, and nobody noticed.

One unremarkable Tuesday, I remember calculating how long it would take my neighbors to realise I hadn’t collected the milk from my doorstep. Three days, I wagered.

Having written a book called Change Your Words, Change Your World, I've spent much of my working life exploring how language affects the way we feel about ourselves, so I’m quite familiar with the idea of self-worth. In theory, at least. In practice, knowing something intellectually doesn't necessarily mean you're proficient at applying it when life gets difficult.

Like you, no doubt, I've caught myself looking for digital reassurance. A message from someone I care about can lift my spirits enormously. Equally, the absence of a reply can fill my head with squirrels and I’ll waste a couple of hours wondering what I've done wrong.

Wanting to feel appreciated is human. The trouble is that other people are unreliable sources of reassurance because they have their own lives to get on with. Sometimes they’re just busy running a taxi service for their kids and don’t get your message until bedtime. Other times they’re having enthralling conversations with their own cats.

Meanwhile, we're wondering whether we've somehow offended the entire human race. It's exhausting. And I wonder how much of that exhaustion comes from constantly looking outside ourselves for something we might be able to offer ourselves.

We’re often much kinder to other people. If a friend tells us she's had a dreadful day, we don't usually ask her to produce evidence; we listen, sympathise, maybe make her a cup of tea. However, when it comes to our own shortcomings, we can be surprisingly dismissive.

Psychologist Kristin Neff has spent years researching self-compassion, including how we can learn to respond to our own challenges with the understanding we'd offer a friend.

It sounds perfectly sensible, doesn't it? But when you’re feeling lonely or discouraged, do you comfort yourself, or spend time forensically investigating what you’ve done to end up that way?

This year I’ve decided to take a different approach. Whenever that familiar feeling of being disappointed or overlooked colors my perspective, I pause and acknowledge what's actually happening.

Is it possible I was hoping someone would call, or do I just need a hug? There's often a little relief in admitting that, even if nothing changes immediately.

It doesn't always work, of course. Some days I'd like the universe to send me a personalised letter of appreciation, preferably on headed paper.

I wonder what I’d say now to the woman who used to drive past that traffic sign. I'd tell her I understood why she was lonely, and that it was perfectly reasonable to miss the life she'd had, even though she might not believe me.

Perhaps that's the thing about learning to validate ourselves. It's easy enough to understand the idea, but quite another matter to feel it. I don't think I've entirely worked it out yet, but I’m getting better at noticing when I’m waiting for someone else to tell me I’m doing all right.

It still feels a little unnatural, but then so did developing an emotional attachment to a traffic sign. I still smile whenever I drive past one and receive my THANK YOU. And I always make sure I'm going at the right speed. It would be a shame to disappoint an old friend.

The market bloodbath just exposed Wall Street’s true fears about U.S. debt, top economist warns

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

There have been competing theories to explain why Treasury yields have risen so much this year, but last week’s brutal stock selloff debunked one of them, according to a top economist.

The 10-year yield has eased in recent weeks as investors seek shelter in Treasuries. But before the latest dip, it shot up more 100 basis points, soaring above 5% and at one point hitting the highest level in 24 years.

The run-up began after the Iran war started in late February, sending oil prices up and raising expectations that the Federal Reserve will hike rates to fight suddenly resurgent inflation.

At the same time, hyperscalers have been flooding the bond market with fresh debt to finance massive capital spending and the AI infrastructure boom, which has kept the U.S. economy running hot and inflation sticky.

That’s competed for investors’ dollars as the Treasury Department taps the bond market to finance the federal government’s $2 trillion budget deficit—and pay interest of the $40 trillion in U.S. debt.

Some on Wall Street have downplayed the spike in yields, saying the deluge of AI debt has crowded out U.S. bonds and forced the Treasury to offer investors higher returns at auctions.

But Robin Brooks, a senior fellow at the Brookings Institution, doesn’t buy that explanation. In a Substack post on Saturday, he said the past week’s market selloff represented a “natural experiment” that puts the competing arguments to the test.

“On one end of the spectrum are people like me who think this is a rising fiscal risk premium as our public debt grows out of control,” he wrote. “On the other end are folks who say it’s hyperscaler debt issuance that’s pushing up yields, so there’s no sign fiscal policy’s in trouble.”

Brooks said corporate borrowing is nowhere near where it was in the IT bubble of the early 2000s, while public borrowing is historically high and more likely driving up yields.

He pointed to the bond market’s reaction to the latest monthly jobs report, which showed payrolls grew by more than double the consensus estimate.

Compared to previous upside job surprises, the two-year yield rose more than what hot economic growth could explain, undercutting the idea that U.S. growth depends on AI as well as the argument that AI is responsible for higher yields.

Brooks also cited the market-implied yield for a 10-year security 10 years from now, which gauges the premium investors demand for the risk of holding Treasuries long term. Such risks include the trajectory of U.S. debt and deficits.

If the AI bubble was pushing up long-term yields, then this “10y10y forward yield” would’ve fallen alongside the 10-year and two-year yields.

“It didn’t and that in my mind further cements the case for the fiscal risk premium,” he said.

“The midterm elections and the AI sell-off that’s ensued have given us the perfect natural experiment to disentangle what’s going on with long-term yields. They’re up because of mounting fiscal stress, not because of AI.”

U.S. debt warnings have been piling up recently. Last month, the Treasury Department’s final tally on fiscal year 2026 showed that the federal budget deficit widened to $1.99 trillion, 12% worse than the $1.78 trillion gap in fiscal 2025.

That came as revenue increased 3% to $5.4 trillion, lagging behind the 6% bump in spending to $7.4 trillion. Social Security and Medicare were the biggest line items, but in third place was interest payments on the national debt, topping defense spending and Medicaid.

Gross interest costs for fiscal 2026 came in at $1.36 trillion, Treasury data show, with an average interest rate of 3.53%. That’s more than double the rate in 2021, just before the Federal Reserve embarked on an aggressive tightening cycle to rein in inflation.

Net interest payments rose 8% to $1.05 trillion, outpacing increases in total spending, revenue and GDP. In fact, it exceeds real GDP growth of about 2% as well as nominal GDP growth of about 6%.

Fiscal 2026’s net interest costs translate to about $2.9 billion a day, and the Peter G. Peterson Foundation estimated they represent 3.2% of GDP, breaking the previous record set in 1991.

“Higher interest begets more debt, and greater debt begets higher rates and higher interest. Eventually, the whole thing could come crashing down,” Committee for a Responsible Federal Budget President Maya MacGuineas said in September.

“That’s why Washington needs a fiscal intervention now, before it’s too late. The President, the Treasury Secretary, and Congressional leadership need to understand the severity of this issue. There are no easy fixes, and we can’t just wish this problem away.”

Characterize First, Then Refactor: A Golden-Corpus Harness With a Mutation Gate

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Most refactors break behavior that no test ever covered. Adding more hand-written tests is slow and biased toward what you already suspect. A pinned behavior snapshot is faster, and a mutation gate tells you whether that snapshot can actually fail.

The rule: pin first, prove the pin bites, then change the smallest thing. If the pin never fails on a deliberate bug, you have documentation, not a safety net.

Choose a target that is boring and load-bearing. Small input surface, no hidden globals, callable from a script. Write the choice down in the commit message.

If the function reads the clock, calls the network, or draws randomness, stop. You need a seam before a snapshot. Pin a wrapper with the bad inputs injected instead.

Build a JSONL file of real-shaped inputs. One case per line, stable ids, keyword arguments. No customer data, no tokens, no emails.

Three sources work well. Existing fixture files, call sites in the repo, and log payloads you have already stripped. Twenty to forty cases covers most small functions.

Include the ugly ones: empty string, zero, negative, missing key, duplicate id. The golden file should pin the error paths too, not just the happy path.

Raw output rarely compares cleanly. Dict ordering drifts, floats repeat, timestamps move. Normalize before hashing.

Normalization is a tradeoff, not a free win. Rounding floats hides small drift. Falling back to type name hides everything inside slot-only objects. Log both decisions in the harness header.

The harness fingerprints each case and stores a sha256. Exceptions are pinned by class name and message.

Run it twice. Once to write, once to confirm the harness is stable. A pin that drifts on a second run is not a pin.

This is the step most people skip. A snapshot nobody has ever seen fail is unverified. So break the code on purpose, one behavior at a time.

Keep each mutant as a tiny patch file. Each one must change real behavior, not formatting.

A MISSED line is the useful output. It names a behavior your corpus never exercises. Add one case, re-pin, re-probe. Repeat until every survivor is a mutant you can prove is equivalent to the original.

A SKIP line proves nothing. A patch that fails to apply, or a mutant that fails to import, is not evidence of coverage.

Now refactor. Rename, extract, inline, move. Re-run the check after every commit.

Example output after a clean extract-method commit: ok: 34 cases unchanged. If a hash moves, the patch was not behavior-preserving. Revert it, split it, try again.

One extra rule keeps this honest. Any commit that updates golden.json must also carry a BEHAVIOR: line in the message. That line explains why the change is intended. A golden diff without that line is a refactor that leaked.

After the refactor, run the mutant loop again. Every mutant that was CAUGHT must still be CAUGHT. Coverage can survive a move while silently degrading.

Two parts of this loop are tedious to write by hand. First, the normalization layer, which needs to survive real shapes you have not seen. Second, the mutant set, which needs genuinely different behaviors rather than nine cosmetic edits.

MonkeyCode's free model access and free server option are relevant here, both as operator-supplied availability claims rather than measured benchmarks. A free model is good at drafting normalize branches for shapes you forgot. It is also good at proposing candidate mutants across comparison operators, defaults, branches, and validation paths. The free server option matters because the mutant loop is a matrix of full test runs. Running that matrix in a sandbox keeps your local credentials and your laptop's patience out of the loop.

Use model output as a proposal, never as a gate. Every suggested mutant needs a human check that it compiles and actually changes behavior. In my experience with generated mutants, the failure mode is equivalent mutants and non-applying patches, not missing ideas. Reject them loudly; a mutant set padded with noise makes the probe look green while proving nothing.

Skip this workflow if you have no reproducible input source. Skipped if the function cannot be imported without side effects, or if the output is dominated by data you cannot legally freeze. Skip it when the real risk is security or concurrency, where a pinned snapshot is silent. And skip it if nobody will maintain the mutant set. A stale probe is worse than none, because it looks like evidence.

The most useful file you will produce is the MISSED list. Save it, and let it drive the next corpus case.

Mastering the Sprint Lifecycle: How to Escape Mechanical Scrum

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 8 • Originally published at aiflowpm.com

Too many engineering organizations fall into the trap of "mechanical Scrum." You know exactly what this looks like. Teams robotically go through the motions, execute the ceremonies, and check the boxes, yet entirely miss the value. The result? Exhausted developers, frustrated product owners, and Sprints that feel like a relentless feature factory.

If your team is constantly rolling over tickets, dreading the daily standup, or viewing the retrospective as a pointless venting session, you have a fundamental problem. Your tech team isn't running Sprints. Your Sprints are running you.

The secret to high-performing teams isn't memorizing Scrum steps. It is mastering the Sprint Lifecycle as a synchronized engine for predictable value delivery and team empowerment. Let's break down how elite software teams elevate these core events from tedious calendar invites into a distinct competitive advantage.

The Sprint Lifecycle is the continuous, time-boxed sequence of Agile events—Planning, Daily Scrum, Execution, Review, and Retrospective—designed to deliver working software iteratively. It matters because when executed with intent, this cycle transforms unpredictable software development into a reliable, feedback-driven value engine.

Agile leadership isn't about enforcing rules blindly. It requires creating an environment where this dynamic cycle breeds trust, speed, and continuous improvement. Moving from a beginner team to an elite one requires shifting your focus from compliance to intent. Here is how you optimize each phase of the lifecycle.

Sprint Planning is the critical starting point where the team defines the exact business value they will deliver over the upcoming iteration and how they will achieve it. The goal is to establish a clear, unified Sprint Goal rather than simply cramming a backlog with random, disconnected tickets.

In low-maturity teams, planning looks like a prolonged negotiation over story points. The Product Owner reads off a list of tickets, the developers try to guess how much they can squeeze into two weeks based on historical velocity, and everyone leaves feeling overwhelmed. There is no narrative. There is just a bucket of tasks.

Elite teams start with the Sprint Goal. This is a single, compelling objective that connects engineering work directly to business outcomes. For example, instead of "complete 40 story points," the goal becomes "enable users to securely reset their passwords via SMS."

Define the "Why" first: What is the most important problem we need to solve in the next two weeks?Pull, don't push: Developers must pull work into the Sprint based on their actual capacity, not have it pushed onto them by aggressive deadlines.Leave slack in the system: Aim for 80% utilization. If you plan for 100% capacity, a single production bug will derail the entire iteration.

The Daily Scrum is a 15-minute tactical synchronization meeting held by and for the developers to inspect progress toward the Sprint Goal and adapt their plan for the next 24 hours. It is an alignment tool to optimize flow, pivot quickly, and eliminate blockers.

We have all attended painful standups. The Scrum Master acts like a project manager, calling on team members one by one. Developers mumble through the three standard questions ("Yesterday I wrote code, today I will write code, no blockers") while everyone else zones out. It is a micromanaged status report that adds zero value.

Ditch the rigid three-question format. Turn the Daily Scrum into a strategy session.

Walk the board: Start from the right side of your Jira (or equivalent) board—the items closest to "Done"—and work backward. Ask: "What do we need to do together to get this specific ticket across the finish line today?"Focus on flow, not busyness: It does not matter if a developer is busy. What matters is if the work is moving.Take it offline: If a technical discussion starts dragging on past two minutes, call a "parking lot" and move it to a post-sync huddle with only the necessary people.

Sprint Execution is the active building phase where the team writes, tests, and integrates code to create a potentially releasable product increment. The primary focus here must be on continuous integration and maintaining high quality from day one, avoiding late-stage technical debt.

In mechanical Scrum, developers code in silos for eight days. On day nine, they throw everything over the wall to QA. Integration conflicts explode. Bugs pile up. The Sprint ends with five tickets sitting in the "In Review" or "Testing" columns, leading to a massive carryover into the next Sprint.

You cannot bolt quality onto a product at the end of a Sprint. You have to build it in.

Swarm on tickets: Stop having five developers working on five separate features. Encourage pair programming and mobbing to finish one feature before starting the next. Limit your Work In Progress (WIP).Shift testing left: Quality assurance isn't a final phase; it is a continuous activity. Write automated tests alongside the code.Strict Definition of Done (DoD): Done doesn't mean "it works on my machine." Done means code is reviewed, tested, integrated, documented, and fully ready to deploy to users.

The Sprint Review is a collaborative working session held at the end of the Sprint to inspect the working software with stakeholders and adapt the product roadmap based on real data and feedback. It is a strategic pivot point, not just a one-way presentation.

Many teams treat the Review as a passive "demo theater." The team shows off a few features to stakeholders who nod silently, applaud politely, and log off. There is no discussion about market changes, user feedback, or roadmap adjustments. Worse, teams sometimes present slides instead of actual working software.

Treat this event as a vital feedback loop. You want stakeholders to actively engage with the product.

Show real software: Never demo from a PowerPoint or a staging environment that isn't representative of production. Inspect the actual increment.Discuss the misses: Be transparent about what you didn't achieve. If you missed the Sprint Goal, explain why and what you learned. This builds immense trust with the business.Adapt the backlog: Spend the last 15 minutes discussing what comes next. Did a stakeholder's feedback just invalidate an upcoming feature? Great. Adjust the product backlog right there.

The Sprint Retrospective is the most critical event in the Agile framework, designed for the team to inspect how they worked together and identify actionable ways to improve their process, tools, and relationships. It requires psychological safety and a commitment to incremental upgrades.

Teams run out of time and skip the Retrospective, or it devolves into a superficial "Start, Stop, Continue" exercise where the same minor complaints (e.g., "too many meetings") are raised Sprint after Sprint without anything ever changing. It becomes an empty ritual.

If you only have time for one Agile event, make it the Retrospective. This is where your team upgrades its own process engine.

Establish psychological safety: Start with the Prime Directive. Everyone must believe that regardless of what was discovered, everyone did the best job they could given what they knew at the time. No blame games.Focus on one clear action item: Do not try to fix ten things at once. Identify the single biggest bottleneck impacting the team right now. Assign accountability: An action item without an owner is just a wish. Assign a specific person to drive the process change in the very next Sprint, and put that action item physically on the Sprint backlog.

Scrum is not a rigid rulebook meant to micromanage developers. It is a continuous rhythm. When you shift your perspective from just checking off calendar events to genuinely mastering the Sprint Lifecycle, everything changes.

Planning becomes purposeful. Standups become tactical. Execution drives quality. Reviews generate crucial business pivots. Retrospectives build unstoppable teams.

Take a hard look at your current iteration. Which phase of the Sprint Lifecycle is currently your team's biggest bottleneck? Stop going through the motions. Identify the mechanical traps in your current process, apply these tactical fixes, and watch your tech team evolve from a stressed-out feature factory into a highly predictable, high-performing value engine.

MCP prompt injection: limit the agent’s blast radius

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 8 • Originally published at span.observer

MCP prompt injection is an instruction hidden in data an agent reads, which pushes it to call MCP tools without the user knowing. A ticket, a log line, a web page or a tool description is enough. No filter stops it reliably, so the realistic lever for an SRE or platform team is to reduce what the agent can do when it gets fooled.

This guide applies that idea in seven steps: inventory the tools, remove the ones that are not needed, make the rest narrow, bound the token, require human approval, separate reading from acting, then trace the calls. It complements our guide to securing an MCP server by focusing on one goal: the blast radius.

The OWASP Gen AI Security Project, in its LLM01:2025 Prompt Injection entry, separates two cases. Direct injection happens when a user’s input alters the model’s behaviour in ways nobody intended. Indirect injection happens when the model accepts external content, such as websites or files, that contains instructions. With MCP the second case is the common one: every read tool is an input channel.

The same entry lists seven strategies, including « Enforce privilege control and least privilege access », « Require human approval for high-risk actions » and « Segregate and identify external content ». The LLM06:2025 Excessive Agency entry covers the other half of the problem: damaging actions triggered by unexpected, ambiguous or manipulated model output, whatever the cause, hallucination or injection. It names three root causes: too much functionality, too many permissions, too much autonomy.

The SRE reasoning is the same as for an outage: not every cause can be prevented, so the impact is contained. An injected agent that only has a read tool on a narrow scope causes a limited confidentiality incident, not a deleted deployment. An agent that answers yes to all three is the dangerous case: it reads text controlled by a third party, then has the means to act and to exfiltrate. The rest of the method breaks that combination.

OWASP words the first measure as « Minimize extensions ». Give the agent only the tools its task needs. A diagnostic assistant does not need to send e-mail; a writing assistant does not need to read production logs. Disable out-of-scope tools or whole servers in the client configuration, and redo the inventory whenever a server is added.

The MCP specification (version 2025-06-18, Tools page) requires servers to validate all tool inputs, implement access controls, rate limit invocations and sanitise outputs. The critical lines are the namespace allowlist, the strict name pattern, the absence of a shell and the maximum duration. Even if an injected instruction asks to « restart everything in production », the tool refuses. These guardrails live in code, not in the prompt, which matches the OWASP measure « Complete mediation »: authorisation is enforced by the downstream system and does not depend on the model’s judgement. For locally launched servers, see also isolating STDIO MCP servers.

The token defines the worst case. The « Security Best Practices » page of the MCP specification (draft version, read on 31 October 2026) describes a progressive model: a minimal initial scope set, for example mcp:tools-basic, limited to low-risk discovery and read operations, then targeted elevation through a WWW-Authenticate challenge with a scope parameter when a privileged operation is first attempted. It also lists common mistakes: publishing every possible scope, and using wildcard scopes such as * or full-access.

One token per use, with an expiry date and an owner, also keeps auditing to a readable perimeter. For observability servers, grant read rights on the data that matters and leave write rights to another token used by another agent (see the case of Dynatrace Assist and its guardrails).

According to the specification’s Tools page, there should always be a human in the loop with the ability to deny tool invocations. Clients should ask for confirmation on sensitive operations and show tool inputs to the user before calling the server, to avoid malicious or accidental exfiltration. OWASP says the same thing: « Require human approval for high-risk actions ».

In practice, sort tools into three levels: read-only without confirmation, reversible write with confirmation, irreversible or outbound action with confirmation and the arguments displayed. Approval fatigue is fought by reducing the number of sensitive tools, not by clicking faster.

The last cut in the combination from step 1: an agent that reads uncontrolled content (tickets, web pages, application logs) holds no write or send tool. It produces a summary or a proposal that a second agent or a human carries out. OWASP recommends to « Segregate and identify external content », and wrapping external content in explicit markers inside the context helps. This reduces the risk without removing it: a poisoned summary remains possible, hence the approval of step 5. For booby-trapped tool descriptions, see our guide to MCP tool poisoning.

The specification recommends that clients log tool usage for audit purposes. The OpenTelemetry semantic conventions for MCP (status Development) define mcp.method.name (required), gen_ai.tool.name (when the span relates to a specific tool), gen_ai.operation.name set to execute_tool for tool calls, and error.type set to tool_error when the result carries isError as true. The attributes gen_ai.tool.call.arguments and gen_ai.tool.call.result are opt-in, because they can hold sensitive data. Setup is covered in our guide to observing MCP agents with OpenTelemetry. It works with any OpenTelemetry backend, Dynatrace SaaS or Dynatrace Managed included, without relying on a feature specific to either.

Useful signals: a write tool called right after external content was read, a spike in refused calls, a tool never seen in the history. All three show the blast radius being tested.

Every time venture capitalists write a check, they’re secretly running numbers in their heads about different exit scenarios. It’s their job as fiduciaries. But nearly all will tell you (publicly, anyway) that every portfolio company is headed for an IPO.

Stephen Ward, the co-founder of Brightmind Partners, a two-year-old cybersecurity fund in New York, says otherwise outright. “You have to sell on the way up,” he says.

Ward’s unvarnished pragmatism is one reason he stands out. Another is the size of his firm’s debut fund late last year: a whopping $250 million fund, which he closed with co-founder Gur Talpaz. A third reason is his résumé, which includes a stint with the Coast Guard, nine years in the Secret Service, and CISO jobs at TIAA and Home Depot before he ever thought about investing.

One proof point that suggests the combination is working is SGNL, the identity security startup CrowdStrike agreed in January to buy for $740 million, 11 months after Brightmind led its Series A.

Now Ward is raising a second fund, targeting roughly the same size as the first one. This time, though, he’ll be doing it without Talpaz, who left in April along with another early colleague, leaving Ward as the firm’s sole general partner. He’s betting on himself at a moment when early-stage cybersecurity startups are raising more money than later-stage rivals for the first time in more than a decade.

His unemotional approach to exits traces back to an unlikely career. Ward says he grew up in northwest New Jersey between two farms, in a family that couldn’t afford college for his older brothers. After high school, he joined the Coast Guard, inspired by a commercial of a man jumping out of a helicopter, though he says he barely knew how to swim at the time. He spent four years in search and rescue.

Afterward, he studied criminal justice at Seton Hall in New Jersey and thought half-heartedly about law school. “I didn’t know what I wanted to do,” Ward told me last week over Zoom, wearing a pale hooded sweatshirt and looking more like a basketball coach than a venture capitalist. “I was kind of lost. I missed the military and the camaraderie and all of that.”

After graduating in 1998, he says, he mailed out some 300 résumés but no one responded. A Seton Hall professor who was also a chaplain to Secret Service personnel, as well as to members of the FBI and CIA, began introducing him around, and the Secret Service called first.

The Secret Service has two primary missions: protecting people and investigating financial crimes. Ward gravitated to investigations, then to “cyber” after the September 11 attacks in 2001. That year, he married a former college classmate, an American-born Syrian Muslim. Colleagues warned him the background check would be “miserable.” (They’re still happily married.)

What came next took Ward’s life down an unexpected path. Stationed in New York, he arrested a hacker who’d pulled off the largest credit card data theft of that era. Instead of charging him, however, Ward flipped him, turning him into an informant and running him for about three years. But the hacker kept hacking behind Ward’s back, and after he was caught again, he told the agency, as a diversionary tactic, that Ward was in on it.

By that time, Ward had left for the private sector, and he ultimately spent roughly 18 months clearing his name. “It was hard to get out of bed,” he said of that period, describing the investigation as “almost like a spouse cheating on you,” given his love of the agency. The hacker ultimately received a 20-year sentence, and Audible bought the rights to the story, turning it into an eight-episode podcast called “Operation Firewall.”

Ward’s corporate career has been a success by most measures, though he describes it as a series of jumps he really wasn’t qualified to make. His first private-sector job at J.P. Morgan, where he was recruited in 2007 to build a cybersecurity unit, was the hardest transition of his career, he says. He felt like “the dumbest person in the room,” missed his Secret Service crew, and twice thought about going back, unaware he was still under investigation. He stuck it out and now calls the investment bank the “best management school.”

Six years as CISO at the financial services company TIAA followed, and then two years at Home Depot starting in 2019. But in 2021, feeling burned out, he quit without anything lined up for the first time since age 16.

That chapter didn’t last long. The founders of Wiz, whose security software Ward had used at Home Depot, put him on a short list for a job at their company. Jeff Horing, a venture capitalist at Insight Partners, which had co-led Wiz’s $100 million Series A round in late 2020, interviewed Ward for the role, then offered him one at Insight instead.

It’s a good-news, bad-news story, given that Wiz was acquired last year by Google for $32 billion. When I asked him about it last week, Ward observed that the friend who took the Wiz job “made life-changing money,” but said it doesn’t bother him.

Regardless, he spent just three years at Insight, where he says he worked on Wiz, Abnormal Security, and Elisity, which IonQ agreed in October to buy for up to $1.3 billion. Then, at age 49, he thought about striking out on his own for the first time.

He says people told him it was a young man’s game. He left anyway and began cold-emailing limited partners. Ultimately, fewer than 20 LPs filled the fund, including Horing.

Ward started Brightmind in 2024 with Talpaz, a CrowdStrike corporate development executive whose deals overlapped with Ward’s during his time at Insight. Tayler Sipperly, another CrowdStrike corporate development alum, was the firm’s third employee.

The partnership ended this past spring. Asked what happened, Ward, using carefully worded legalese, cited “differences in opinions regarding operations and the future of Brightmind.” In August, Talpaz and Sipperly co-founded a new venture firm with Elia Zaitsev, CrowdStrike’s global CTO for the past three years. Called Cognition, it’s now reportedly targeting a $170 million first fund to back cybersecurity startups.

Sipperly says that he and Talpaz “continue to support the existing Brightmind portfolio companies as well as its limited partners” and that they “remain on the board of a number of the Brightmind portfolio companies.”

Brightmind’s first fund has made 14 investments to date, with one exit: that SNGL sale.

Some investors asked why Brightmind didn’t ride out that bet even longer. But Ward says he’s seen enough across his career that he feels confident in warning founders when they’re “going to race past the turn.”

In cybersecurity, he says, the best sales come between a startup’s third and seventh years. Indeed, he says his team tracks every security acquisition and what buyers are building versus buying. If Palo Alto Networks is likely to buy something, he says, CrowdStrike will experience “FOMO, then Zscaler is going to look over and go, ‘What did they just do? I should probably do the same thing.’”

Understanding how the pieces fit together is the trick, Ward explained, offering some hypotheticals. If CrowdStrike is building a product, he said, it’s unlikely to buy a portfolio company that makes something similar. Palo Alto Networks might love a company, but not if buying it would force its customers to switch away from something it bought five years ago.

“It’s very easy to go, ‘Good match,’ ‘terrible match,’” he said. “And that’s really what we spend a ton of time figuring out.”

He has timing on his side, at least. Early-stage cybersecurity startups are outraising their later-stage rivals for the first time in more than a decade, according to PitchBook, which counts $4.7 billion worth of seed-through-Series B deals through September.

That total is already ahead of the entirety of 2025, even though the number of deals fell to 248 from 358 last year. Seed rounds in particular are ballooning, per PitchBook. The average cybersecurity seed round jumped to $8.4 million in the first nine months of this year, from $5.54 million a year earlier.

Ward questions how much of that money is really going to AI security. By PitchBook’s count, 278 deals in the first half of 2026 were bucketed as such, but his team’s manual review found only 30 true ones. He doesn’t think Anthropic or OpenAI will “take over the security world,” but instead will do “just enough.”

For real-time protection, which he terms “zero second,” he favors cyber-specific models that run locally on a customer’s own systems, like that of Empirical Security. He also looks for startups that could trounce established companies that he considers vulnerable, name-checking 27-year-old Qualys and 24-year-old Tenable.

Ward says Brightmind’s second fund won’t be entirely cybersecurity, focusing about 20% on AI infrastructure deals. He expects a meaningful number of teams to come from Israel, too. (Roughly 40% of the debut fund’s startups are based in Tel Aviv.)

Asked about the founders he’s most comfortable backing, the response is immediate: second-time founders who stick together.

Brightmind is comprised of five people right now: COO Iva Messy, also a Seton Hall graduate, came from venture firms Felicis and Andreessen Horowitz (a16z) on the recommendation of Ward’s cousin, Carl Eschenbach, a former Workday CEO who is now back at Sequoia. Sven Wollschlaeger, a Midwesterner whom Ward calls one of the hardest-working people he’s known, spent three years alongside Ward at Insight and is a principal at Brightmind.

CTO Jamie Mneimneh, whom Ward first hired at Home Depot as a distinguished engineer, is the most technical person of the team. He built the cloud computing environment on AWS where the firm tests startups’ products. Mneimneh also built the AI agents that now source most of Brightmind’s deal flow, which is how the firm avoids hiring a bench of analysts and keeps management fees down, says Ward.

Taylor Cleveland, Ward’s chief of staff at Home Depot, joined the firm a few months ago.

For all the career changes, Ward says the real force driving him hasn’t changed. He grew up without money and still worries it could happen again, saying he’s being paid to produce a “3x net fund,” and he’s “not going to celebrate until we get that.”

Said Ward: “I don’t know what’s wrong with me. I have a level of being very naive to like, not being qualified to do something. I’ve just always looked at people and been like, ‘Okay, you know more than me today, but tomorrow, it’s going to be a little less, and the day after that, it’s going to be less, and eventually, I’m going to catch you and surpass you, and I’m going to know more than you.’ That’s how competitive I am.”

How much Netflix cost in 2007 vs. 2026

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

The company is notorious for frequent price hikes.

Movie fans of a certain age may vividly remember the sad, somewhat rapid decline of the old video store. Whether your store of choice was the nearest Blockbuster or an independent shop, you probably smile at the nostalgia of heading to the video store on a Friday or Saturday night, anxiously hoping that a copy of the hottest new release was in stock. Or, better yet, just returned by another renter so you could swoop in and snag the last one.

Then streaming came along, and video stores around the world began fading into irrelevance, with locations closing as streaming services continued to grow in popularity. In 2006, Blockbuster — the undisputed king of video rental stores — made a last-ditch effort to stay current by offering Total Access, which allowed customers to exchange their mail-ordered DVD rentals in physical stores.

If you've only ever known Netflix as a streaming service on your smart TV, tablet or phone, you might find it interesting that, in 2007, Netflix could only be streamed on a Windows PC with Internet Explorer. And the video quality wasn't great. After all, high-definition (720p and 1080i) was just starting to take off as a mainstream viewing format in 2007. Netflix's streaming library of roughly 1,000 titles was pretty lean, as well. Its first original series was still five years away, and the first original Netflix movie didn't debut until 2015. But none of this stopped its prices from increasing — a true Netflix staple.

Over the next decade, Netflix added some new plans like Premium, Standard, Basic, Standard-definition-only, Basic with ads, Ad-Free and other iterations. And with those plans typically came annual price hikes, usually ranging from $1 to $3 more per month depending on the plan.

Today, Netflix offers three plans. Standard with ads costs $8.99 per month and includes ad-supported access to most (but not all) shows and movies in the Netflix catalog, with the ability to stream and download in 1080p HD on two supported devices at a time.

The Standard plan is $19.99 per month and includes everything in the Standard with ads package (minus the ads, of course), but with completely unlimited access to Netflix TV shows, movies and games. It also offers the option to add one extra member who doesn't live with you to the plan for another $7.99 per month to let them endure commercials, or $9.99 a month for the ad-free experience.

Finally, the Premium plan costs $26.99 monthly and offers unlimited access to the entire Netflix library, with video available in 4K Ultra HD + HDR with Netflix spatial audio, the ability to watch Netflix on four supported devices simultaneously and download on six supported devices, and the option to add up to two more members who don't reside with you for the same respective add-on prices per month as Standard.

Netflix has become notorious for its near-annual price hikes over the past 20 years. But if you really analyze what you get today compared to what you got in 2007, one could argue that today's plans give you better value for your money. Of course prices have increased since 2007. It's been 20 years, and our economy has been put through the wringer a number of times during that span.

Suno is facing yet another pair of lawsuits. A group of rights holders of Elvis Presley’s music and the publisher of some of Eminem‘s biggest records are suing the AI music company, claiming it illegally generates music and lyrics that mimic those artists. The lawyers in the Presley suit claim that Suno has violated Tennessee’s Ensuring Likeness Voice and Image Security (ELVIS) Act, which makes it illegal for an AI company to clone a singer’s voice.

In the suit, lawyers representing Presley’s rights holders argue that “Suno has mechanically encoded itself with artists’ identities, hard-work, creativity, and time, and harnessed them all for a consistent conveyor belt ofcold hard cash.“ These suits closely mirror one filed by Jason Isbell and others in September, which claimed Suno created imitations of the plaintiffs but did not claim copyright infringement directly.

Later in the complaint, the lawyers write that “Suno’s ravenous race to the bottom aims to make human creativity obsolete, coldly replicating without a license in seconds what takes years to learn, struggle with, maintain, and endlessly attempt to make better and perfect.”

Suno spokesperson Cat McCormack told The Verge that, “Suno exists to help people create new, original music, not to trade on anyone’s name or likeness, and we prohibit any unauthorized use of an artist’s work. To protect against this, we do not allow prompts for specific artists’ names and songs and work with third-party providers to screen uploaded audio files and lyrics for potential misuse. We are always working to strengthen our guardrails and we will continue to add new safeguards that protect artists and our users.”

This adds to the pile of lawsuits Suno is currently facing from Sony, UMG, Isbell, Reservoir Media, and more.

Gloating Emails To A Newspaper Solved The Arson Spree That Hit 125 SUVs In One Night

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

In the early morning hours of August 22, 2003, in West Covina, California, vandals damaged one building and 125 SUVs across four dealerships and a private neighborhood with paint nd destroyed others with firebombs. The vandals spray-painted messages like "I love POLLUTION" and "SUV = TERRORISM". Most of all, they repeatedly painted the acronym "ELF," linking them to the Earth Liberation Front, a leaderless, loosely organized activist group. ELF targeted property and managed to avoid causing serious physical harm to anyone in hundreds of credited attacks from the late 1990s through the 2000s. The government branded ELF a terrorist group, partly because ELF used destructive tactics like arson, which is a common tool of militant groups. And, in fact, multiple SUVs were set on fire that night in 2003.

Either way, the government knew they were looking for passionate environmentalists. Within just a couple of weeks, the feds arrested a suspect, Josh Connole. Connole was a peace activist, vegetarian, and solar panel sales rep. He drove an EV and lived at a commune. All of those things seemed to make him a perfect fit for a particular kind of profile.

But Connole wasn't the guy. After his arrest was announced, a reporter at the LA Times received the first of multiple emails from "Tony Marsden" that read, "The police have the wrong man here. I was amongst those responsible for the SUV attacks."

Was the sender concerned about an innocent man paying for their crimes? Maybe, but some gloating was involved, too. "We left plenty of clues, none of them pointing to Josh," the message said, then added smugly, "The FBI hasn't seemed to pick up on any of them, which makes the whole ordeal very boring for us, the true culprits." To prove his involvement, he noted that he had spray-painted an equation by Leonhard Euler, an 18th-century Swiss mathematician, on one of the SUVs. That was a detail that hadn't been released to the public.

His boredom wouldn't last long, as the emails would be traced to his college, Caltech. Apparently, he couldn't be bothered to send the emails from another location. Law enforcement seized multiple computers from the school and found a cache of the email messages on one of the machines, sent right after the sender checked his own messages. The actual sender of the email, as you might have guessed, was not named "Tony Marsden." His name was William "Billy" Cottrell, and he was going for his PhD in theoretical physics at Caltech.

If Billy thought that he could successfully deny sending the emails or his involvement in the spree, that wouldn't last long. Investigators soon matched his DNA to a headband found at the scene of the crime. For Billy, the jig was up.

At first, Billy told investigators he wouldn't implicate anyone else in the spree, but later blamed the arson part of it entirely on his friends, Tyler Johnson and Michie Oe. According to Billy, whose statements are a little self-serving and should probably be taken with a grain of salt, Tyler and Michie showed up that night and convinced him to go spray-paint some SUVs with them. Billy wouldn't have seen this as an odd request, since he and Tyler had recently planned to plaster a couple of hundred SUVs with bumper stickers that said, "My SUV supports terrorism," though that plan fell through.

The three hit one dealership, then another before moving on to a private neighborhood where they vandalized some more SUVs. It was in that neighborhood where Tyler, according to Billy, set the first SUV on fire. Billy claimed that Tyler had never told him about plans to set anything on fire, and he objected when Tyler used the first firebomb. Supposedly, Tyler said it wouldn't happen again. But Tyler didn't stop, and more SUVs were set ablaze at the last dealership hit that night. In fact, a Molotov cocktail accidentally hit Billy's clothes, setting them on fire. He quickly took off his shirt, which is how his headband wound up on the ground for investigators to find.

A few emails later, police had Billy in handcuffs. Johnson and Oe were later named as unindicted co-conspirators, but had fled the country before they could be arrested.

Billy's defense team had few options. They had to draw a line between spray painting, which wasn't a federal crime, and arson, which, in this context, it was. But Billy's attorney came up with an additional defense — Asperger syndrome. Asperger syndrome is a diagnostic term, since dropped by the World Health Organization, for a form of Autism that does not include intellectual or language impairment. His attorney hired a medical professional who later diagnosed Billy with the condition.

The defense claimed that his diagnosed condition kept Billy from picking up on social cues that would have told him that Tyler was lying about stopping at just one firebombing. When it came to figuring out other people's motives, as reported by Los Angeles Magazine, his lawyer asserted that Billy's brain was like "'a slow computer' with a dial-up Internet connection." That seems like an odd way to describe the brain of a doctoral candidate researching theoretical physics. Still, Billy did fit the common, if ill-informed, stereotypes of adults with Autism spectrum disorder with high intelligence. Why didn't he bother to drive to another location to send those emails? He had to get back to his theoretical physics work.

It could be considered a questionable defense strategy, given the estimated 5 million U.S. adults with Autism Spectrum Disorder and most of them, we assume, don't go around vandalizing SUVs. The judge would rule that Asperger's couldn't be used as a defense, but that ruling didn't come until the prosecution had almost rested its case.

A jury found Billy guilty of seven counts of arson and conspiracy to commit arson. The judge sentenced him to over eight years, which included three years added because of the supposed terrorism aspect of the crime. He was also ordered to pay $3.5 million in restitution.

Billy didn't do well in prison, even getting into a fight. It seems he tried to change the channel on the TV to the news when the other inmates wanted to watch "I Love Lucy". His ordeal prompted one of his former professors to write a letter detailing the emotional effects prison conditions were having on Billy. The professor got several prominent physicists, including Stephen Hawking, to sign the letter. It turns out that Billy's case had prompted an intense interest in the scientific community, with many expressing the view that imprisoning someone of his intelligence was depriving the world of the theoretical advancements he could be making. The letter worked, and Billy would be transferred to a different prison to serve out the rest of his sentence.

Eventually, the arson counts were thrown out, and Billy's entire sentence was vacated on appeal because his Asperger's diagnosis wasn't allowed to be used as a defense. The appellate court kept his conspiracy conviction, though, and sent the case back to the trial judge, who resentenced Billy to eight years for the remaining charge, meaning he would have to serve the same amount of time.

Billy was finally released in 2011. After he got out, he finished his PhD in 2017 at the University of Wisconsin–Madison, then held postdoctoral positions at the University of Amsterdam and Stanford University. He would go on to work at Jump Trading and teach a course on cryptocurrencies at the University of Chicago. Overall, things didn't turn out too bad for him. After all, the government has vowed to seek harsh penalties for this kind of crime, and the current administration has even threatened to send perpetrators of similar crimes to El Salvador.

What about his friends? Tyler Johnson fled to Europe and eventually wound up on the island of Corsica. He got by working odd jobs and even founded a nonprofit that supplied solar-powered ovens to households in impoverished communities. He also liked to hike the mountains, which would lead to his tragic death in 2010 in an avalanche. A documentary entitled "Finding Tyler" would be filmed about him after his death.

As far as we can tell, Michie Oe has never been caught. Her name doesn't appear in any law enforcement arrest databases we can search. Whether Billy actually participated in the arson that night or was only a willing participant in the spray painting is anyone's guess. But so far, he's the only one who has paid the price for what happened.

The Legend of Zelda: Ocarina of Time Thankfully Resists FromSoftware’s Influence

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Ocarina of Time sticks to the basics, and the remake is better for it

This year in video games, I’ve swung a digital sword more times than I can count. Thrilling action games like Onimusha: Way of the Sword and Phantom Blade Zero have gotten the feel of a sword fight down to a science, as steel clashes and sparks fly in spectacular fashion. But my favorite duels of the year aren’t in any of this year’s most razor-sharp action games; they’re all in The Legend of Zelda: Ocarina of Time.

The Switch 2 remake builds on the combat of Link’s 1998 adventure in careful but effective fashion. The Master Sword feels more powerful than ever thanks to killer sound design and a bit of visual pizazz on impact. What the remake doesn’t do, however, is change Link’s moves to give him the most widely used trick in modern action games: the parry. There’s no deflection to be found in Ocarina of Time’s remake, and that makes a seemingly simple combat system stand out in an unexpectedly refreshing way.

Compared to many modern games, Ocarina of Time’s swordplay doesn’t require much mastery from players. Aside from a charged spin attack and a leaping slash, Link’s offensive options are limited. Lock on, swing the sword, hit the enemy, and that’s basically all you need to know. Sure, you can block attacks with your shield or use one of your items to switch it up, but you’re always going to follow the same motions to take out a Deku Baba with consistent strikes.

One of my questions heading into the remake was about how much Nintendo would modernize that approach. After all, lots of remakes and remasters these days make reworked combat a priority; just this year, we’ve seen that in projects like The Witcher 3: Wild Hunt Remastered and Assassin’s Creed Black Flag Resynced. Rather than following that wave, Nintendo chose to keep Link’s offense relatively unchanged. That can take some getting used to if you play a lot of modern action games that all seem to have some version of a parry, or at least some kind of counterattack.

The quicker you acclimate to Ocarina of Time’s throwback action, though, the quicker you’ll come to appreciate its elegance. Fights aren’t meant to be long duels against evenly-matched opponents; Link is a master of his craft and can dispatch virtually any enemy in a few hits. Precision and timing are key as you patiently wait for your opening before lunging forward with a strike. The same goes for Link’s evasive maneuvers, which allow him to sidestep and backflip away from incoming attacks. It only takes a few Stalfos encounters to learn their attacks and lock down the right dodge and attack follow-up timing to take one out quickly.

In my review, I compared that to the experience of playing Punch-Out!!. The classic NES game’s staying power comes from the fact that every fight hinges on you learning each enemy’s tells and reacting to them accordingly. Every boxing match is a dance, and you have to learn your half of it. Ocarina of Time functions the same way, pushing you to hit all your marks rather than rush through a careful fight.

There are several fights in Ocarina of Time that test your ability to follow that flow, especially the late-game Iron Knuckles who hit like a truck if you fail to dodge their attacks. The best skill check, though, comes during a clash with Dark Link in the Water Temple. It’s the one time where you find yourself up against a fighter who is as efficient and precise as you, because it is you. Patience is your greatest skill in a battle that will taunt you for swinging wildly while your shadowy foe seemingly has an answer to every mistake you make. It plays out like a theatrically staged fencing match. Once you feel that, every other fight clicks into place, too.

Though it may sound a little simple, Nintendo finds the right way to make every slash feel powerful. Every sword hit is accompanied by an impactful thwack and an explosion of colorful particles. Even slashing the weakest enemies as Young Link feels spectacular, as if your blade has busted them open like a pinata. Those small touches make every hit feel important and satisfying to execute, rather than futile hits against a sponge. I can’t say the same for something like GameFreak’s summer not-quite-a-Soulslike Beast of Reincarnation, where bosses fall to death by a thousand cuts.

It may sound strange to call a combat system rooted in 1998 design fresh, but it really is in a world where so many action games I play feel like variations on a theme. Ocarina of Time may not impress modern players who look for expression in their combat, but you won’t hear anyone labeling it a Soulslike or dubbing it “parryslop.” The battles have an unmistakable texture to them, born out of a focused design philosophy that suits an equally focused swordsman. Who needs a parry when no blade can cross you?

Marketers Are BURNED OUT - And No One Gives AF

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

I have read countless posts about bloated marketing roles where six jobs are crammed into one title. One listing asked for a “Marketing Manager” to handle brand strategy, paid media, SEO, email marketing, copywriting, and front-end web design. All of that... on a junior salary! These are not rare. They are the norm these days. Scroll LinkedIn or Reddit for five minutes and you will see post after post of people venting about being stretched thin, underpaid, and told to be “grateful for the opportunity.”

I have been reading these for a YEAR now. Watching the same story play out. Marketers are asking, “Is it just me, or has marketing completely lost the plot? Is this the job I wanted? Should I just switch careers?” I even asked the same things myself. I used to love marketing. Now, I don't even know what to say.

What even was marketing before all of this? Was it always like this and we are just noticing it now? Or did it get worse in the last few years?

What used to be a blend of strategy and execution turned into survival mode. AI promised efficiency. Instead, it created more expectation. Faster turnarounds. More output. Tighter budgets. Leadership sees AI as a shortcut, not a tool. So the workload? It went up. Headcount? Went down. Pressure? TRIPLED.

The marketer role did not evolve. It got gutted and repackaged.

This article is not about the trends. Not the hype. Just focusing on the one question we all dread to be answered. How real is marketer burnout, and how did we get here?

What happens when your creative energy gets consumed by meetings, client briefs, and endless edits? How do you stay motivated when everyone blames your team for poor performance but no one credits you when a campaign wins? Why do marketers, especially in digital, feel like they are always running on empty?

Burnout in marketing is not new. What’s different now is how fast it spreads and how deeply it affects people across roles. From content specialists and media buyers to strategists and SEO managers, burnout is everywhere. Not because people are lazy or bad at their jobs. They are overwhelmed, underappreciated, and stuck in systems that demand more while offering less.

Marketers today wear too many hats. Generalist roles stretch across brand, analytics, operations, and sales support. It used to be enough to run great creative. Now you are expected to prove ROI, optimize in real-time, adjust to AI tools, and still produce on-brand messaging across ten platforms. The second something underperforms, marketing takes the fall.

But when results are good? Sales or other department will take the credit. That’s not an exaggeration. One Reddit comment I saw earlier hit it perfectly: “The sales team shouldn't be the only ones getting commission since we (content team) did all the work.” That’s the norm in many agencies and in-house teams.

Marketers drive interest, create value, and nurture leads. Sales closes once the hard part is already done.

There’s a word for that dynamic: exhausting.

Burnout is tied to more than just being busy. It’s the layoffs. The increased cost of living. The consolidation of roles. Managers freeze raises. Employees fear losing their jobs, so they overperform to avoid the next round of cuts. That creates a cycle. You take on more. You work harder. You don’t complain. And then your reward is more responsibility, not more support. Not a better salary.

You become your own bottleneck. You say yes to everything because the team is small and leadership needs “just one more push.” Eventually, you hit a wall. Creativity dies. Enthusiasm fades. Work turns into survival.

Marketing roles are highly visible but rarely respected. Everyone thinks they can do your job. Leadership gives vague direction but expects strong positioning. Product teams shift priorities mid-sprint. Sales wants new decks with impossible turnaround times. People expect you to spin gold out of nonsense with a smile on your face.

Meanwhile, your inbox fills up with subject lines like “quick tweak,” “minor edit,” and “urgent request.” These aren’t minor. They’re entire projects disguised as favors. And they never stop.

This is why boundaries matter. The problem is, setting boundaries gets seen as being “difficult” or “not a team player.” So people stop trying. They take the hits in silence.

A common theme in marketing burnout is the rejection of sales culture. Some marketers say, “I don’t want to do sales. I’m an introvert.” That mindset makes you easy to ignore in corporate environments. One Reddit commenter put it plainly. Marketing is sales. You sell ideas to bosses, value props to clients, and narratives to users. You’re not on the phone closing deals, but you are pitching all the time.

People who thrive in marketing know how to talk. They present data with confidence. They make their case without waiting for approval. They build allies. And yes, sometimes they party with clients to keep them loyal.

The problem is not that marketers don’t work hard. It’s that most of them don’t get taught how to sell themselves. That disconnect builds resentment over time.

Fixing burnout in marketing requires more than taking a week off or downloading a mindfulness app. Companies and leadership need structural change.

1. Credit needs to be shared. If a campaign brings in leads, content, media, and analytics should all get credit. This is not a favor. It’s the truth! Stop handing out bonuses to sales without acknowledging who did the heavy lifting.

2. Boundaries must be normalized. No one should work weekends to chase someone else’s last-minute idea. Make deadlines real. Protect personal time. Normalize saying no.

3. Redefine performance. Measuring success only through ROI creates a narrow path to burnout. Not every channel performs the same way. Not every campaign wins in thirty days. Look at long-term impact, brand growth, and engagement quality.

4. Advocate up the chain. Teach marketers how to pitch. Not just to customers. To leadership. Make the case for headcount, for tools, for strategy. If you don’t make noise, you won’t get noticed.

5. Say the quiet part out loud. Marketers need space to admit when they are tired. When they feel ignored. When they need clarity. Create a culture where people can be honest without fear.

Burnout doesn’t mean you are in the wrong field. It means the structure around you is broken. You shouldn’t need to chase credit. You shouldn’t need to hide exhaustion. You shouldn’t be constantly afraid of layoffs or budget cuts or being replaced by automation.

Good marketing is emotional work. It requires A LOT of creativity, patience, and most importantly clarity. You cannot fake that for long. At some point, your output suffers and your health goes with it.

There is a way forward, but it starts with truth. Stop pretending everything’s fine. Start fixing the real problems.

If your team is burned out, they don’t need a pep talk. They need help. Give them that, or lose them.

5 unexpected uses for your old smartwatch

Breath new life into your old tech with these handy tips.

Upgrading to one of the best smartwatches can be exciting, but it often means your old smartwatch is left with nothing to do. Unfortunately, it's at this point that users may toss their old smartwatch in a drawer and forget about it. But it doesn't have to be like that.

Your old smartwatch is a versatile piece of hardware, so despite how it seems, that small device that's been gathering dust still has some pretty unexpected and interesting uses. With the right guidance, you can give your old smartwatch a new lease on life, or at the very least, you could sell it for some quick cash. Even if your smartwatch no longer receives major OS updates, you can still use it as a dedicated AI tool, an easy-access note-taking device, a child monitoring tool, or a dedicated sleep tracker. So free your old smartwatch from its drawer and blow the dust off. Most of these unexpected uses only take a few minutes to set up and require an extra app or two, though some require a cellular plan or a phone for full functionality.

If you use AI tools like Gemini or ChatGPT, one of the more relevant uses for your old smartwatch is to turn it into a dedicated AI assistant device. Setting things up is pretty simple, allowing you to get answers from or talk to your AI, all without having to pull out your phone. On Wear OS smartwatches, Gemini is the primary option. While on the Apple Watch, Siri is the default — but you don't have to stick with Siri.

On watches running Wear OS 4 or later, you'll need to first make sure Gemini is installed and has been updated. Once that's sorted and voice activation is enabled, all you need to do is say "Hey Google," and Gemini will respond. If voice activation isn't your style, you can alternatively press and hold the side button to activate Gemini. On Samsung watches, you'll need to customize the side button so it can activate Gemini. To reassign, open Settings > Button and gestures > Double press > scroll to where you see Gemini and select it.

On the Apple Watch, activating Siri is straightforward; simply raise your wrist and say "Hey Siri" or press and hold the Digital Crown. You can use the Wrist AI app to gain ChatGPT or Gemini functionality, but the free tier only allows a small number of chats daily. For easier access, you can add a Wrist AI complication to your watch face. For Wear OS watches, to get ChatGPT going, you'll need the WristAssist app, but it's been removed from the Play Store, so you will have to sideload it. You'll also need an API key from OpenAI to get things going; creating the key is free, but usage is billed.

A good use case for your old smartwatch is simply making it a note-taking device thanks to more accurate AI transcriptions. So instead of having to pull out your phone from your pocket every time you get an idea or want to jot down some thoughts, you can raise your wrist and speak.

Your old smartwatch likely already has a note or voice recorder app, so what you need is preinstalled. On Apple Watch, you can say "Hey Siri," then "Record a voice memo" to get started.

You can get transcriptions of the notes recorded on both Wear OS watches and Apple Watch, but you'll need your phone. On Samsung watches, you can get transcriptions in the voice recorder app using the built-in speech-to-text mode, but it has a 10-minute limit. Recordings taken on your smartwatch should automatically sync across your devices, so a note you recorded during your morning walk should be waiting on your phone by the time you get home.

There are few things as important to the human body as sleep, and your old smartwatch can help you improve it. But you'll have to sacrifice charging your watch overnight, potentially leaving you with a drained battery in the morning. And that's precisely where your old watch comes in. You can charge it all day, then wear it to bed while your main smartwatch charges.

Setup usually takes just a few minutes. To track your sleep and view your sleep data on Apple Watch, set up Sleep in the Health app on your iPhone, then turn on the Track Sleep with Apple Watch setting. For a Galaxy Watch, connect the watch to your phone, then open the Sleep tile on your Galaxy Watch and follow the prompts to get it set up. Keep in mind that how well this works and how much data it can track depends on the model of your smartwatch, because they don't all offer the same sensors, especially older models.

Lastly, don't treat the reported numbers with the same weight as a diagnosis from your doctor, because sensors can be inaccurate. So, if you notice anything concerning in your sleep report, take it as a cue to talk to your doctor, not as a diagnosis.

Your old smartwatch can find a new purpose on your child's wrist as a dedicated kids' watch. When set up, your kids can call, text, and share locations without owning a smartphone. Do note that this only works on LTE/Cellular smartwatches, and a smartphone isn't needed for the child after configuration.

Samsung watches have a dedicated Kids mode that gives parents plenty of oversight over their child's experience. So apart from the usual location monitoring, calls, and texts, parents can also approve or block apps, set School Time limits, and use Google Family Link to manage the child's watch usage. Unfortunately, Kids mode isn't available on every Samsung Watch; you'll need an LTE Galaxy Watch 6 and above.

Apple Watch offers a similar feature called Apple Watch for Your Kids, and it's supported on Series 4 or later with cellular, or an SE with cellular on watchOS 7 or later. As you'd expect, it can make calls and send texts, has location tracking, screen time management, and Schooltime mode, which, like Samsung's equivalent, is basically restricted so the child doesn't get distracted during school hours.

Keep in mind that cellular features require a carrier plan, which means additional fees for you. And carrier support varies, so some carriers may not support standalone calling from a smartwatch.

If none of the uses work for you, or you'd just prefer to get rid of your device, then your best option is to sell your old smartwatch. It probably still holds some resale value; it's only a matter of finding the right place (or way) to sell it. There are two main routes to go with.

First, you can sell on marketplaces like eBay. Selling on a marketplace may give you the highest payout, but it also comes with the most hassles. You'll have to handle everything concerning the sale, including writing an accurate listing, taking clear pictures, setting a good price, answering questions from window shoppers, shipping it, and then calculating how much platform fees cost you.

Selling to a buyback company like Greenbuyback is the second option that will likely net you less than a marketplace, but it can be more convenient. Simply get a quote online, then ship your old smartwatch to the buyer. Once it's received, it'll be inspected, and if the condition you described matches, you get paid. If it doesn't, you can receive a revised offer. How long the whole process takes depends on the specific program; some pay in as little as 24 business hours after receiving your watch, while others can take up to five business days.

If you don't mind getting store credit and less value for your old smartwatch, then you can trade in your old smartwatch to retailers like Best Buy or manufacturer programs like Apple Trade In. Before you sell or trade in your old smartwatch, make sure to unpair it from your phone and wipe it. On an Apple Watch, unpairing erases it. On Wear OS, sign out of your accounts and factory reset it.

Meet the 27-Year-Old Who’s Trying To Bring Housing Back to Rural Ohio

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

When it comes to the hottest locations that attract young 20-somethings, Mansfield, OH, probably isn't the first place that comes to mind.

For years, Mansfield’s nickname was “The Fun Center of Ohio” because of its family-friendly attractions and its status in the 1970s as a mini-bike manufacturing hub.

More recently, the town of 47,000, located halfway between Columbus and Cleveland, earned the local nickname of “Danger City” after the Westinghouse electric plant left in 1990 and the town fell into deep economic decline.

The 27-year-old serial entrepreneur, who started a painting and landscaping business as a teenager, relocated to Mansfield from Seattle a year ago, hoping to revitalize rural housing through his vertically integrated housing development company, Western Dominion Land.

Vertical integration is a development model in which a single company controls the full life cycle of a housing project.

“In other countries, they’ve figured out that vertically integrating construction means you’re not paying a margin out to every single step," Goehner explains. "If you own the system—from a lumberyard, to producing panels or modular, to buying the land, to developing the land, to building the homes—you're not paying everyone’s markup along the way, and you can actually deliver that home at a reasonable price.”

Goehner is building a factory in Mansfield to produce structured panels that he says will cut single-family home construction from months to weeks and allow him to charge much less than other builders. The first panels are expected to roll off the production line in early 2027.

Currently, it takes 8.8 months to construct a home from start to finish, according to the National Association of Home Builders. Goehner says his process allows a home to be built and move-in-ready in 40 days.

Western Dominion has already built about 500 housing units across Ohio, starting at $200,000 for a single-family home.

Western Dominion focuses on what it calls "attainable housing"—homes priced below what the median household income in the area can afford but not income-limited, meaning they work for the vast majority of families and buyers.

In Mansfield, where the median listing price is $229,000, he says, "single-family homes at $215,000 sold instantly. At $260,000, they sat for months."

As he sees it, 25% of the homes on the market are priced for 60% to 70% of buyers, while the rest of what’s being built is at the top end of the market. Furthermore, only 8% of construction happens in rural areas, despite 20% of the population living there.

"The government is too focused on low-income housing" and low-income housing tax credits, he says. “And the last few housing bills they passed were only structured to deliver essentially more urban multifamily units and incentivize builders to build more low-income housing with tax credits."

In rural communities, he adds, “We have a terrible amount of aged housing inventory. Most of our homes are from before 1970, which would be fine if it didn't cost so much to remodel.

“From the '90s to the 2000s, we’re building a good amount of homes. As a country, we were doing about 1.6 million a year. And then in rural America, we were doing about 220,000 homes a year. And then 2008 hits, and that drops down to about 60,000 homes a year in rural America."

Along the way, smaller builders disappeared, and larger builders were disincentivized from building in rural areas because of the red tape involved.

"If you want to build in rural America and you go to a bank, unless you have all the cash, you have to show comps," he says. "You've got to be, like, ‘All right, we think these homes are going to sell for this much because these guys sold for this much.' And if no one's built for five to 50 years, which is the case in a lot of these communities, that can be difficult."

The added costs of building in rural areas, like having to pull utilities, "mean you're spending $25,000 to $50,000 per lot before you can even start putting a house on it or connecting your utilities to the lot."

Since the COVID-19 pandemic, home prices in rural communities have risen sharply. A Realtor.com® housing analysis of home prices from November 2019 to November 2025 found that median listing prices increased more than 70% in rural counties while in-metro counties saw home prices increase around 30% during the same time period.

"A lot of the politicians we talk to, they go, 'I didn't know that that county needed housing. I didn't know rural needed housing because the population is shrinking.' But then when you look at why the population is shrinking, it's because they haven't gotten any new homes for 20 to 40 years."

"You've got this huge demand. But on paper, on the surface, it looks like there's no demand because the population's declining," he continues. "And that's how you get cities like Holiday City."

Holiday City, near the Ohio border with Indiana and Michigan, has a population of just 48 people, but it is home to three large businesses—Chase Brass & Copper Co., 20/20 Custom Molded Products, and a Menards Distribution Center—which draw around 1,500 commuters from out of state.

"Let's put up, you know, 300 homes, and a portion of the workforce can actually stop commuting an hour or two every day," Goehner says.

Goehner hopes Ohio's new slate of elected officials will help advance rural building by offsetting some of the infrastructure-related costs of building in rural areas. In exchange, he would sell homes at his “attainable” housing rates.

"The government needs to stop spending thousands of dollars a month per unit to subsidize rents when they could simply spend a little bit upfront to make it viable to build at a reasonable price point again," he says.

PHP's per-directory .user.ini files are configuration, but they can influence which code runs before a requested script. The auto_prepend_file directive names a file that PHP parses before the main file, as if it had been loaded with require. If an application permits an attacker to create or modify a .user.ini file in the document tree, a temporary upload or template-write flaw can become a persistent execution path.

The manual says .user.ini processing is available for the CGI/FastCGI SAPI. PHP scans from the requested script's directory upward to the document root, and only settings in the allowed modes are recognized. auto_prepend_file is a per-directory setting. The file is resolved with include_path, which adds another configuration value to the review.

An uploaded file is usually not executed directly. The problem begins when a user can place content in a directory that PHP scans for .user.ini, or when a deployment process writes generated files beside application code. The next request in that directory can inherit settings that the application did not intend.

The cache matters. user_ini.cache_ttl controls how often the per-directory configuration is reread. A response to an incident may remove a malicious file while a running FastCGI worker retains the previous setting for some period. Treat the cache as part of containment, not as a reason to assume the file is harmless.

The risk is not limited to a file named shell.php. A prepended file can contain initialization logic, logging hooks, or code that changes the application's runtime. Reviewers need to look at who can write any path that may be treated as configuration and at what code that configuration can include.

Inventory all document roots and every writable directory below them. Include uploads, cache, generated thumbnails, plugin directories, and deployment release folders that are web-accessible. Search for .user.ini files and for auto_prepend_file or auto_append_file references in deployment templates. Check for symlinks and path normalization differences between the web server and PHP.

Inspect the effective PHP-FPM configuration for user_ini.filename, user_ini.cache_ttl, open_basedir, include_path, and allow_url_include. Confirm whether web-server location rules deny requests to dot files and whether the denial covers every virtual host and alias. An application-level 404 is not a filesystem restriction if PHP still scans the directory.

Review the deployment user's write permissions. A release process that can replace application code is highly privileged; it should not also accept untrusted filenames or extract archives into the live document root. Separate writable data from executable code, and keep the web process unable to create PHP files where it can also write configuration.

If per-directory configuration is not required, set user_ini.filename to an empty value and deploy the decision through the PHP-FPM pool configuration. Where it is required, deny direct access to .user.ini, set a short cache lifetime appropriate to the deployment, and make the file immutable by the web user. Use open_basedir to bound file access, and do not allow remote inclusion unless the application has a documented and reviewed need.

Set a trusted include_path and disable URL wrappers for application files. Protect the FastCGI socket and pool configuration from unprivileged users. A user who can change the pool configuration can bypass many application-level controls.

In a staging copy, create a harmless .user.ini that points auto_prepend_file at a test file, then request a script in that directory. Confirm that the test file is included and record the cache delay. Remove the file and repeat the request after the cache expires. Try the same path through the public web server, an alias, and any alternate hostname.

Review application logs for changes to .user.ini, unexpected include failures, and requests for dot files. Correlate those events with upload and deployment activity. The useful control is a path boundary: untrusted data must not be able to change which code PHP loads before the application starts.

But following the stock market's parabolic climb, concerns are mounting about a possible AI and/or quantum computing bubble-bursting event. While history hasn't exactly been kind to next-big-thing technologies -- every game-changing technology has endured an early-innings bubble-bursting event since the mid-1990s -- there's an even more prominent bubble that looks ready to burst, based on what history tells us.

While history shows that the AI and quantum computing bubbles should eventually burst, the $1.5 trillion outstanding margin debt bubble may be the spark that upends the stock market's four-year rally.

"Margin" is money an investor borrows from their broker, with interest, to wager against (short-sell) or purchase securities. When margin is used to buy stocks or exchange-traded funds (ETFs), it represents a form of leverage.

Using margin can be risky. If an investor's wager moves in the desired direction, they can quickly amplify their gains. But if a stock or ETF moves in the opposite direction, losses can be quickly magnified. This dynamic makes outstanding margin debt a somewhat crude, yet intriguing measure of investors' willingness to take risks.

From a historical standpoint, the short-term outlook for Wall Street's AI- and quantum computing-driven rally isn't pretty. If history rhymes once more, investors can expect a sharp bear market downturn in the presumed not-too-distant future.
